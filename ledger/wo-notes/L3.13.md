## C. ข้อต่างจากใบงาน (พร้อมเหตุผล)

1. **"on-device หรือ server" เป็นการเดาที่ดีที่สุดเท่าที่ API ให้ ไม่ใช่คำตอบจากเครื่อง** — ใบงานสั่งให้ตั้ง
   `requiresOnDeviceRecognition` เมื่อ "`supportsOnDeviceRecognition()` และ locale อยู่ใน supportsRecognition on-device"
   แต่ของจริงในแพ็กเกจ 57.1.0: `supportsOnDeviceRecognition()` ถาม `SFSpeechRecognizer()` **ตัว default ของเครื่อง**
   (ไม่ใช่ตัวของ locale ที่จะใช้) และ `getSupportedLocales()` ฝั่ง iOS คืน `installedLocales = supportedLocales`
   เป๊ะ ๆ (ดู `ios/ExpoSpeechRecognitionModule.swift:393`) ⇒ ไม่มีทางรู้จาก JS ว่าภาษานั้นมีรุ่นออฟไลน์จริงไหม
   จึงใช้ "รองรับ on-device + ภาษานี้อยู่ในรายการที่รู้จำได้" เป็นเงื่อนไข และพึ่งฝั่ง native ที่ถอยให้เองอย่าง
   ปลอดภัย (`ExpoSpeechRecognizer.swift:588` ใส่ flag ให้เฉพาะเมื่อ recognizer ของ locale นั้นรองรับจริง มิฉะนั้นวิ่ง
   server ต่อโดยไม่ล้ม) ⇒ **บรรทัด log บอก "โหมดที่ขอ" ไม่ใช่ "โหมดที่ Apple ใช้จริง"** (หนี้ข้อ 1)
2. **เงียบ ≠ เครื่องพัง** — ใบงานมี 3 ข้อความ (denied/listening/unavailable) แต่ error จริงมีมากกว่านั้น
   `NO_SPEECH`/`SPEECH_TIMEOUT`/`ABORTED` จึงพาไมค์กลับสถานะพักโดย**ไม่ขึ้นข้อความใด ๆ** (ขึ้น "เครื่องนี้ทำไม่ได้"
   ตอนผู้ใช้แค่ไม่ได้พูด = โทษเครื่อง/โทษผู้ใช้ผิด ๆ) · `NOT_ALLOWED` ที่มาจาก event (ไม่ใช่จากกล่องขอสิทธิ์) ก็เข้า
   ทาง denied ⇒ ได้ปุ่มเปิด Settings เหมือนกัน
3. **เพิ่มคีย์ที่ 4 `advisor.mic.openSettings`** — ใบงานระบุ 3 คีย์ แต่ป้ายบนปุ่มก็เป็นข้อความที่ผู้ใช้เห็น จะฮาร์ดโค้ด
   ไม่ได้ (rule 7)
4. **แตะ `src/ui/Composer.tsx`** (ใบงานเปิดช่อง "ถ้าจำเป็น" และข้อสอบ T1.14 ยอมรับ `Animated` ที่ไฟล์นี้) — ผลพลอยได้
   คือ **หน้าเช้าได้ปุ่มไมค์เต้นแบบเดียวกันฟรี** ซึ่งตรงกับที่ทั้งสองจอใช้ composer ตัวเดียวกันอยู่แล้ว
5. **เพิ่ม cleanup ตอนออกจากห้องที่ปรึกษา** (ไม่มีในใบงาน): เดินออกจากจอกลางประโยคเคยทิ้งเซสชันรู้จำเสียงวิ่งต่อ
   หลังจอที่มองไม่เห็นแล้ว — S4 ถือว่าเสียงเป็นของอ่อนไหวที่สุดในแอป
6. **`app.config.ts` ดึงข้อความ speech ออกมาเป็นค่าคงที่** แทนที่จะพิมพ์ซ้ำในสองที่ — ข้อความเดิมคำต่อคำ (ยืนยันจาก
   `Info.plist` ที่ prebuild ออกมา) แต่เป็นการแก้บรรทัดที่ใบงานไม่ได้สั่ง

## D. หนี้ที่ยังไม่ปิด

1. **ยังไม่เคยรันบนเครื่องจริงสักครั้ง** — ทั้งใบนี้ verify ด้วย typecheck/ข้อสอบ/prebuild/export/ภาพจากเว็บเท่านั้น
   เว็บไม่มี speech recognition (ได้แต่เส้นทาง "ไม่รองรับ") ⇒ partial/final/สิทธิ์/โหมด ต้องพิสูจน์ที่ R1 (build #8)
2. **log โหมดเป็น `console.log` ไม่ใช่ audio event** — ใบงานเปิดให้เลือก "audio event/console" เลือก console เพราะ
   `AudioEvent` ของ `@lucid/engine` เป็นสายของเสียงกลางคืน (bell/whisper) การยัด event ชนิดใหม่เข้าไปกระทบ schema
   วินิจฉัยและ consumer (ดูบทเรียน outbox) ⇒ อ่านโหมดได้จาก Xcode console/`expo start` เท่านั้น ยังไม่เข้า diagnostics
3. **หน้าเช้ายังใช้ข้อความรวมอันเดียว** (`common.notAvailableOnThisDevice`) ทุกกรณี รวมทั้งตอนถูกปฏิเสธสิทธิ์ และ
   **ไม่มีปุ่มเปิด Settings** — ใบงานสั่งแค่ "อย่าแตะ logic เพิ่ม" จึงไม่แตะ · ควรยกชุด denied/Settings ไปหน้าเช้าในใบถัดไป
4. **ยังไม่มีภาพของสถานะ "กำลังฟัง" และ "ถูกปฏิเสธ" ในห้องที่ปรึกษา** — เว็บไปไม่ถึงสองสถานะนั้น (ตายตั้งแต่
   `isAvailable()`) ที่วัดได้คือปุ่มไมค์เต้นจากแกลเลอรี `/dev/ui` ⇒ ต้องดูของจริงตอน R1 ว่าบรรทัด "กำลังฟัง…" ไม่ดัน
   composer และปุ่ม "เปิดการตั้งค่า" ไม่ชนแถบแท็บ
5. **`continuous: false` = ผู้ใช้หยุดพูด ~3 วิ แล้ว iOS 17- จะปิดเซสชันเอง** (iOS 18+ รอ final) — ประโยคยาวที่เว้นวรรค
   คิดนาน ๆ อาจถูกตัดจบก่อน ถ้า R1 เจอปัญหานี้ต้องเปลี่ยนเป็น `continuous: true` + ปุ่มหยุดเอง (ตอนนี้ปุ่มหยุดมีแล้ว)
