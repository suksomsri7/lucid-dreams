### 1.2 เวลา + เอนเวโลป + ทิมเบอร์

```
โน้ตละ 2.0 วิ · เริ่มห่างกัน 1.0 วิ (ซ้อนกันเสมอ 2 ตัว)
env(t) = ( min(1, t/1.0) · min(1, max(0, 2.0−t)/1.8) ) ^ 1.3
ฮาร์มอนิก (ตัวคูณ, เกน) = (1, 1.0) (2, .45) (4, .15) (6, .05) — **ทุกตัวเล่นซ้อน 2 ชุด ±0.8%**
reverb: convolution กับ IR = noise × exp(−t/τ) · decay 2.8 วิ · τ = decay/6 · ir[0]=1 · หารด้วยค่าสูงสุด
mix: 0.45·dry + 0.55·3·wet → lowpass ค่าเฉลี่ยเคลื่อนที่ 64 แซมเปิล → normalize พีค 0.7 → เฟด 50 ms หัว-ท้าย
durationMs = 4×1000 + 2000 + 1000 + 2800 = **9800** · whisperAtMs = **2600**
```

* **ทิมเบอร์เป็นของแต่ละคน**: เกนของฮาร์มอนิกตัวที่ 2/4/6 สุ่ม ±10% ของค่าฐาน · detune สุ่ม 0.007–0.009
  (ค่าที่เจ้าของฟัง = 0.008) · ตัวมูลฐานคงที่ 1.0 เสมอ
  เหตุผล (วัดแล้ว ไม่ใช่เดา · `.heavy/check-uniqueness.mts`): ทำนองที่เป็นไปได้ทั้งหมดมีแค่ **3,401 แบบ**
  ⇒ 1,000 seed ให้ทำนองต่างกันเพียง **832 แบบ** ถ้าแฮชแค่โน้ต+ภาษา ข้อสอบ G2 (1,000 seed = 1,000 hash)
  **ตกทันที** ตามปัญหาวันเกิด · ใส่ทิมเบอร์เข้าไปแล้ว: 1,000 → 1,000 · 10,000 → 10,000 ·
  **50,000 seed → 50,000 hash ไม่ซ้ำ** และตรวจ 200,000 โน้ต: อยู่ใน midi 33–57 ครบ · ก้าวเกิน 7
  หรือซ้ำตัวติดกัน **0 ครั้ง**
* `hash` = FNV-1a 64 บิต ของ `{notes, noteMs, gapMs, envelope, timbre, reverb, lang}` (ตามใบสั่ง: โน้ต + ทิมเบอร์ + ภาษา)
* **ห้องเสียง (reverb) เป็นของกลาง ไม่ใช่ของคน** — `REVERB_ROOM_SEED = 'lucid.anchor.room.v2c.9'` ดู §3.2

### 1.3 การเรนเดอร์ (`renderSignaturePcm`) — TS ล้วน ไม่มี AudioContext

* convolution ตรง ๆ = 9.8 วิ × 2.8 วิ ที่ 48 kHz ≈ **6×10^10 คูณ** (เป็นนาทีใน JS · บนมือถือ)
  ⇒ เขียน **FFT radix-2 iterative** เองในไฟล์ (engine ห้ามมี dependency) + ใช้ท่ามาตรฐาน
  "สองสัญญาณจริงใน FFT เชิงซ้อนเดียว" (ใส่ dry เป็นส่วนจริง · IR เป็นส่วนจินตภาพ แล้วแยกสเปกตรัมคืน
  ด้วย `X[k]=(Z[k]+conj(Z[N−k]))/2`, `Y[k]=−i(Z[k]−conj(Z[N−k]))/2`) ⇒ **2 ทรานส์ฟอร์ม ไม่ใช่ 3**
* twiddle ทำเป็นตาราง (ไม่ใช่คูณสะสม) — คูณสะสมบน 2^20 จุดเพี้ยนระดับ 1e-9 ซึ่งได้ยินเป็น noise หางไฟล์
* วัดจริงบน VPS (เครื่องว่าง · 3 รอบ): **เต็ม 9.8 วิ = 0.37–0.45 วิ** · **ตัวอย่างสั้น 3 วิ = 0.15–0.23 วิ**
* ⚠️ **แก้ตัวเลขที่เคยรายงานไว้**: รอบแรกผมวัดได้ 1.7–1.9 วิ และวัด "ลูป expect ของข้อสอบ = 16 วิ"
  ตอนที่มีงาน python หนัก (convolution ตรง ๆ ของต้นแบบ) ค้างอยู่เบื้องหลังเต็ม CPU — ตัวเลขนั้น**เชื่อไม่ได้**
  ค่าจริงบนเครื่องว่างคือ **~8.3 µs ต่อ 1 expect** (ไม่ใช่ 34 µs) · บทเรียน: วัดเวลาต้องดู `uptime`/งานเบื้องหลังก่อน
* **positive control ของ FFT** (กันกรณี "ผลออกมาเนียนแต่ convolution ผิด"): เขียนต้นแบบเดียวกันด้วย
  numpy `np.convolve` แล้วเทียบกับ TS บนโน้ตชุดเดียวกัน — ได้ **rms 0.1266 เท่ากันถึงทศนิยม 4 ตำแหน่ง**
  และการแบ่งพลังงานตามย่านต่างกันไม่เกินไม่กี่เปอร์เซ็นต์ ⇒ FFT convolution ในนี้ให้ผลเท่ากับ
  convolution ตรง ๆ ไม่ได้เลื่อนเวลาหรือเพี้ยนสเกล

### 1.4 `renderSignatureShortPcm(sig, seconds = 3, sampleRate = 48000)` — ตัวอย่างสั้นสำหรับหน้าทดสอบหู

(เพิ่มตามข้อสอบ G6 ที่ Fable เขียนมาใหม่ · export คู่กับ `anchorWhisperText`)

* คืน **ช่วงต้นของระฆังใบเดียวกันของคนนั้น** ไม่ใช่เสียงใหม่ — ใช้สายการผลิตเดียวกันทั้งหมด
  (ห้อง + lowpass + normalize 0.7) ต่างกันแค่ความยาวและ **เฟดท้าย 300 ms** (ตัวเต็มเฟด 50 ms)
* เลือกโน้ตด้วยกฎ "เหลือเสียงก้องอย่างน้อย 1 ช่วงจังหวะก่อนจบ" ⇒ ที่ 3 วิ ได้ **โน้ต 1–2**
  (โน้ตที่ 3 เริ่มที่ 2.0 วิ = พอดีขึ้นสุด attack 1.0 วิ แล้วโดนตัด ฟังเหมือนไฟล์เสีย)
* ตรวจแล้ว: ยาว 144,000 แซมเปิลพอดี · พีค 0.700 · แซมเปิลสุดท้าย 0.0000 · **correlation กับ 2.7 วิแรก
  ของไฟล์เต็ม = 0.97** (ต่างเพราะไม่มีโน้ตที่ 3 + normalize ของตัวเอง) ⇒ เป็นเสียงเดียวกันจริง
* เหตุผลของฟีเจอร์: หน้าทดสอบหูเล่นซ้ำ 2–5 รอบต่อข้าง — ถ้าใช้ไฟล์เต็ม 9.8 วิ ผู้ใช้ต้องนั่งฟังเกือบนาที
  ก่อนตอบ · ไฟล์เต็มเล่น **ครั้งเดียวตอนจบหน้าหูขวา**

## 2. เซิร์ฟเวอร์ `/ai/anchor`

### 2.1 ท่า ffmpeg ใหม่ (`buildMixFilter`)

```
[0:a] aformat(48k/mono/fltp), volume=0.9                              → [a]   ระฆัง 9.8 วิ
[1:a] aformat(48k/mono/fltp), atempo=0.85, volume=1.1, adelay=2600    → [b]   กระซิบ ครั้งเดียว
[a][b] amix=inputs=2:duration=longest:dropout_transition=0:normalize=0        รวม ไม่ปรับเกนเอง
→ libmp3lame 128k · -ar 48000 · -ac 1 · -map_metadata -1 (ไบต์ต้องนิ่ง)
```

* **`atempo` ต้องมาก่อน `adelay`** ไม่ใช่หลัง — ถ้าสลับ ตัวหน่วง 2600 ms จะถูกยืดเป็น 3059 ms ด้วย
* `dropout_transition=0` สำคัญขึ้นกว่าเดิม: กระซิบจบราว 5.5 วิ แต่ระฆังดังต่อถึง 9.8 วิ — ถ้าไม่ปิด
  amix จะดันหางระฆังขึ้นมา (ได้ยินชัด)
* `delayMs` ที่ route ส่งเข้ามา = `signature.whisperAtMs` (engine เป็นเจ้าของ "เมื่อไร" · mixer เป็นเจ้าของ "ดังเท่าไร")

### 2.2 กระซิบเสียงเดียวทั้งระบบ

* ข้อความ = `anchorWhisperText()` เสมอ · เรียก vendor ด้วย `lang: 'en'` **ตายตัว** ไม่ว่า body จะขอ th หรือ en
* คีย์แคชกระซิบ = `sha256(ประโยค｜en｜เสียง)` ⇒ **จ่ายเงินครั้งเดียวทั้งผลิตภัณฑ์** (เดิมจ่าย 2 ครั้ง = 2 ภาษา)
* `lang` ใน body เหลือ 2 หน้าที่: แยกแถวแคช/`hash` (คนละไฟล์ต่อภาษา แต่ **ไบต์เท่ากัน**) และตัวหนังสือบนจอ
  (`anchorPhraseFor` ยังคืนไทย/อังกฤษตามเดิม ใช้แสดงผลเท่านั้น — `dreamPlan`/`advisor`/`openrouter` ไม่ถูกแตะ)

### 2.3 คีย์แคชของไฟล์ผสม (เปลี่ยนคำนำหน้า)

```
sha256( "anchor|v2c" | whisperAtMs | 0.9 | 1.1 | 0.85 | seed | lang | voice | signature.hash | sha256(ไฟล์กระซิบ) )
```

* เดิมคือ `anchor|1700|0.8|…` ⇒ **ของ v1 เลิกถูกเสิร์ฟเองอัตโนมัติ ไม่ต้องล้าง `tts_cache` มือ**
  (สำคัญ เพราะ `signature.hash` ของ seed เดิมก็เปลี่ยนอยู่แล้ว แต่คำนำหน้าเป็นหลักประกันชั้นที่สอง)
* ทุกตัวเลขที่เปลี่ยนไบต์อยู่ในคีย์ครบ: วันหลังเจ้าของสั่ง "กระซิบช้าอีกหน่อย" แก้ค่าเดียวแล้วของเก่าหลุดเอง

### 3.1 ถอดค่าจากไฟล์อ้างอิงก่อนเขียนโค้ด

* ยาว **9.799979 วิ** (470,399 แซมเปิล @48k mono) · พีค **0.69995** ⇒ ตรงกับ durationMs 9800 + normalize 0.7
* หาโน้ตด้วย Goertzel ต่อหน้าต่าง 0.25 วิ: **73.4 → 61.7 → 92.5 → 110 Hz** เริ่มที่ 0/1/2/3 วิ
  = midi **38, 35, 42, 45** = pentatonic minor บน **35** (root ก่อนลดอ็อกเทฟ = 47)
* หางเสียง: RMS ตกใต้ 1% ของพีคที่ ~6.0 วิ

### 3.2 เลือกห้องเสียง (ค่าที่ใบสั่งไม่ได้ระบุ: การสุ่ม noise ของ IR)

เรนเดอร์ **โน้ตชุดเดียวกับไฟล์อ้างอิง** ผ่าน engine TS แล้วเทียบ 16 การสุ่ม:

| | พลังงานใต้ 80 Hz | 80–160 | 160–320 | corr ของ RMS envelope |
|---|---|---|---|---|
| `sigv2-C.wav` (อ้างอิง) | 56.97% | 39.18% | 3.45% | – |
| ห้องที่เลือก (`…room.v2c.9`) | **52.5%** | **42.1%** | **5.2%** | **0.852** |
| ห้องที่แย่สุดในชุด | 25.8% | 69.1% | 4.3% | 0.601 |

**บทเรียนที่ได้จากการวัด (สำคัญกว่าตัวเลข)**: ถ้าสุ่ม IR จาก hash ของผู้ใช้ (ตามที่คิดไว้ตอนแรก)
โน้ตเดียวกันจะดัง/เบาต่างกันได้ถึง **10 dB** ระหว่างผู้ใช้สองคน — เพราะ IR 2.8 วิ มีหวี ~0.4 Hz
และโน้ตที่นี่คือโทนบริสุทธิ์ 60–200 Hz ยาว 2 วิ (ตกลงบนซี่เดียวของหวี) วัดได้จริง: โน้ต 61.7 Hz
กินพลังงาน 57% ของไฟล์ในการสุ่มหนึ่ง แต่ **8%** ในอีกการสุ่ม ⇒ ไม่ใช่ลายนิ้วมือ เป็นการเสี่ยงโชคว่า
เสียงสมอของใครจะเหมือนที่เจ้าของอนุมัติ **จึงตรึงห้องเป็นค่าคงที่** (ทำนอง+ทิมเบอร์ยังเป็นของแต่ละคน)

## 6. จุดที่ทำต่างจากใบสั่ง (ทั้งหมดผ่านมติ Fable แล้ว 24 ก.ย.)

1. **root ของบันไดเสียง = 45–52 ไม่ใช่ 50–57** — **Fable อนุมัติ**: "เสียงที่เจ้าของอนุมัติสำคัญกว่าตัวเลข
   ที่ผมเขียนมาตรง ๆ" · หลักฐานที่ใช้ตัดสิน: ไฟล์ `sigv2-C.wav` เป็น pentatonic minor บน midi **35**
   ⇒ root ก่อนลดอ็อกเทฟ = **47 ซึ่งอยู่นอก 50–57** และ 45–52 เป็นช่วงเดียวที่ให้หน้าต่างตรงข้อสอบ G3
   (33–57) พอดี · ถ้าใช้ 50–57 ระฆังของทุกคนจะสูงกว่าที่เจ้าของเลือก 3 เซมิโทน–1 อ็อกเทฟ
2. **แก้ข้อสอบเก่า B2/B5 ของ `L1.5b-tts.test.ts` เอง** (Fable สั่ง: เป็นข้อสอบของ builder ไม่ใช่ oracle)
   * `B2` เดิมยืนยัน "ไฟล์ยาว = 1700 + กระซิบ" (คือระฆัง ≤ 1800 ms ของ v1) และ "มีช่วงเงียบก่อนกระซิบ"
     → เปลี่ยนเป็น **เทียบกับ `signature.durationMs` ±300 ms** + ตัดด่านช่วงเงียบทิ้ง (v2-C ไม่มีแล้ว)
     + เพิ่มด่านว่ากระซิบดังอยู่จริงในช่วงของมัน
   * ⚠️ ด่านใหม่ต้องวัด **ความถี่ของกระซิบ ไม่ใช่ RMS รวม** — เพราะระฆังดังที่สุดพอดีตอน 2.0–2.2 วิ
     (ก่อนกระซิบเริ่ม) RMS รวมจึงไม่โต · ใส่ Goertzel เล็ก ๆ (`toneRms`) ในไฟล์ข้อสอบแทน
   * ⚠️ และต้องวัดที่ **440 Hz (คลิป `en` ของ fake vendor) ไม่ใช่ 320 Hz (คลิป `th`)** — เพราะ v2-C
     เซิร์ฟเวอร์ขอ vendor เป็นอังกฤษเสมอแม้ body จะส่ง `lang: 'th'` · จุดนี้เป็นหลักฐานของมติในตัวมันเอง
   * `B5` เดิมยืนยัน "ไฟล์ th ≠ ไฟล์ en" → เปลี่ยนเป็น **ไบต์เท่ากัน** (กระซิบอังกฤษเสียงเดียวทุกคน)
     ส่วนแถวแคช/`hash` ยังต่างกันเหมือนเดิม · ไม่ลบข้อนี้ทิ้งเพราะยังคุ้มค่าในฐานะด่านของ "คนละแถว เสียงเดียว"
   * ข้อสอบอื่นในไฟล์นั้น **ไม่ถูกแตะ** (B1, B3, B4, B6–B11 ผ่านเหมือนเดิม)
3. **`packages/engine/vitest.config.ts` กลับเป็นของเดิมแล้ว** (ไม่มี `testTimeout`) ตามที่ Fable สั่ง
   * ที่ผมเคยรายงานว่า "ลูป expect ของ G5 กิน 16 วิ จึงต้องขยายเพดาน" — **วัดผิด** เพราะตอนนั้นมีงาน
     python หนักค้างเต็ม CPU อยู่เบื้องหลัง · วัดใหม่บนเครื่องว่าง: 1 expect ≈ **8.3 µs** ⇒ G6
     (144,000 แซมเปิล) = **1.2 วิ** + เรนเดอร์ 0.2 วิ · ทั้งชุด engine ผ่านด้วยเพดาน 5 วิ (รันยืนยัน 2 ครั้ง)
   * G5 เวอร์ชันใหม่ของ Fable (สุ่มตรวจ ไม่วน expect) ใช้เวลา **0.44 วิ**
4. **`atempo` ทำในกราฟ filter เดียวกัน ไม่ใช่ ffmpeg pass แยก** — ในกราฟมันอยู่ก่อน `amix` จริง
   ผลเท่ากันแต่ประหยัด 1 process + 1 ไฟล์ temp และไบต์ยังนิ่ง
5. **แก้ `apps/api/.env.example`** ซึ่งไม่อยู่ในรายการไฟล์ แต่ใบสั่งสั่งให้อัปเดตคอมเมนต์ (แก้คอมเมนต์เท่านั้น
   + เปิดใช้ `TTS_VOICE=Sarah` ที่เคาะแล้ว)
