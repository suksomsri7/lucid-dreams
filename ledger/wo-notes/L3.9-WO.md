# ใบงาน L3.9 — R1 hotfix #1: จอ Devices (onboarding + ก่อนนอน)

เจ้าของติดตั้ง TestFlight 0.1.0 (1) แล้วเจอ 25 ก.ย. 2026 (ภาพหน้าจอ iPhone iOS 27 ภาษาอังกฤษ):
1. กด **Find another device** ใต้ Pulse/motion → เด้งกลับหน้าแรกของ onboarding
2. กด **Find another device** ใต้ Sound → ชีตขึ้น "Bluetooth headphones / Speaker" แต่กดอะไรไม่ได้เลย
3. (ผมพบเพิ่ม) การ์ด Sound ขึ้น "No headphones found yet" **เสมอ** และการ์ด Pulse ไม่รู้จักนาฬิกา

## สาเหตุ (Fable ไล่แล้ว)
- (1) `app/_layout.tsx` ด่าน `!hasOnboarded && !inOnboarding → <Redirect href="/onboarding">` · จอสแกนอยู่ที่ `/plan/find-devices` ⇒ ระหว่าง onboarding ถูกเด้งทุกครั้ง
- (3-เสียง) `src/platform/ios/IosAudioPlayer.ts` `status.route` **ไม่เคยถูกตั้งค่า** (null ตลอด) ⇒ `refreshDevicesFromPlatform` ลบ HEADPHONES entry เสมอ ⇒ readiness AUDIO ไม่ผ่านตลอดกาล · expo-audio ไม่มี API อ่าน output route ⇒ ต้องมีโมดูล native เล็ก
- (2) `AudioSearchSheet` แสดงชื่อ 2 แถวเป็นข้อความเปล่า ไม่มี onPress
- (3-นาฬิกา) `connected = paired && appInstalled` ⇒ ถ้ายังไม่ติดตั้งแอปบนนาฬิกาผ่านแอป Watch จะขึ้น "No pulse device" โดยไม่บอกว่าต้องทำอะไร

## งาน builder (apps/mobile เท่านั้น · ห้ามแตะ packages/* apps/api scripts/qc-*)
### A route สแกน BLE ใน onboarding
- แยกเนื้อจอ `app/plan/find-devices.tsx` เป็น `src/devices/FindDevicesScreen.tsx` (prop `onDone`/ที่กลับ) · `app/plan/find-devices.tsx` และใหม่ `app/onboarding/find-devices.tsx` เป็น wrapper บาง ๆ · onboarding/devices.tsx push `/onboarding/find-devices` · กลับ = `router.back()` ถึงจอ Devices เดิม สถานะรีเฟรช

### B โมดูล native `apps/mobile/modules/lucid-audio-route` (โครงเดียวกับ `lucid-focus`)
- Swift `LucidAudioRouteModule.swift`: `Function("getCurrentRoute")` → `{ portType: String, portName: String } | nil` จาก `AVAudioSession.sharedInstance().currentRoute.outputs.first` · `Events("onRouteChange")` จาก `AVAudioSession.routeChangeNotification` (ส่ง payload เดียวกัน) · `OnStartObserving/OnStopObserving`
- `index.ts` + `expo-module.config.json` (`ios.modules`) + podspec · Android/web = stub คืน null (rule 8)
- `src/platform/ios/audioRoute.ts`: จำแนก `portType` → `'headphones' | 'speaker' | 'other'` (BluetoothA2DP/BluetoothHFP/BluetoothLE/Headphones/USBAudio/AirPlay/CarAudio = headphones · BuiltInSpeaker/BuiltInReceiver = speaker) + ชื่อแสดง = `portName`
- `IosAudioPlayer.getStatus().route` = ชื่ออุปกรณ์เมื่อเป็น headphones · `null` เมื่อ speaker/ไม่มี · subscribe onRouteChange → อัปเดต status + เรียก `refreshDevicesFromPlatform()` (ผ่าน callback/emitter ที่มีอยู่ ไม่ import วน)
- **ลำโพง**: `src/devices/prefs.ts` เพิ่ม `audioSpeaker: boolean` (persist เหมือน phoneOnMattress) · `registry.ts`: ถ้า `audioSpeaker` และ route ปัจจุบันเป็น speaker (หรือไม่มีหูฟัง) → add AUDIO entry id `speaker-route` ชื่อ i18n `devices.speaker.name` ("ลำโพง iPhone"/"iPhone speaker") connected:true battery:null · เจ้าของบอก "user จะใช้อุปกรณ์อะไรก็ได้" — ลำโพงใช้ได้ แต่ต้องเลือกเอง
- รีเฟรชเมื่อกลับจาก Settings: `AppState` 'active' → `refreshDevicesFromPlatform()` (ทั้ง onboarding/devices.tsx และ plan/devices.tsx หรือทำกลางใน registry.ts ครั้งเดียว)

### C ชีต Sound ทำงานได้
- แถว **หูฟัง Bluetooth**: กด → `Linking.openSettings()` (ห้าม `App-Prefs:` — App Store ปฏิเสธ) + ข้อความ `onboarding.devices.search.audio.openSettings` "เปิด Settings → Bluetooth จับคู่หูฟัง แล้วกลับมา หน้านี้จะอัปเดตเอง" · ปุ่มมี chevron/ลูกศรให้รู้ว่ากดได้
- แถว **ลำโพง**: กด → toggle `audioSpeaker` (สวิตช์ `Switch` ที่มีใน src/ui) + `speakerHint` "เสียงกระซิบจะออกลำโพงเบา ๆ — วางมือถือใกล้หมอน" · เมื่อเปิด → การ์ด Sound ขึ้น "ลำโพง iPhone · พร้อม" จุดเขียว
- ชีตเดิมบนเว็บ (fixture) ต้องยังเรนเดอร์ได้เพื่อ QC

### D นาฬิกา
- ใน registry/จอ: ถ้า `paired && !appInstalled` → แสดงบรรทัด `devices.watch.installHint` "จับคู่แล้ว · ติดตั้ง Dreaming บนนาฬิกาผ่านแอป Watch (เลื่อนลง Available Apps)" ใต้ชื่อ Apple Watch · ถ้า `!paired` คงข้อความเดิม
