## 5. ข้อแย้ง/หมายเหตุกับสัญญา WO + บั๊กที่จับได้เอง

### 🔴 N-1 — ทุก literal ไทยในโค้ด (ไม่ใช่แค่ string ที่ผู้ใช้เห็น) โดน fitness rule B จับ รวมถึง comment
**อาการ**: `npx tsx scripts/fitness.mts` รอบแรกตก 7 จุด — ไม่ใช่แค่ข้อความ UI แต่ **comment ที่ยกคำไทยมาอ้างอิง mockup** (เช่น `/** ... "เริ่มคืนนี้" ... */`) และ **ข้อมูล keyword ภาษาไทยในโค้ด** (`keywords: { th: ['ฉลาม','ดำน้ำ',...] }` ที่ผมตั้งใจไว้สำหรับเดาธีมจากข้อความอิสระ) ก็โดนจับเหมือนกัน เพราะ rule B สแกนทุกบรรทัดของไฟล์ ไม่แยก string-literal จาก comment

**วิธีแก้**:
1. Comment ทุกจุดที่เคยยกคำไทยมาอ้าง → เขียนใหม่เป็นอังกฤษล้วน (อ้างชื่อ i18n key หรือแปลความหมายแทนคำจริง)
2. **ตัดการเดาธีมจาก keyword ภาษาไทย/อังกฤษทิ้งทั้งหมด** — เปลี่ยน `themeFromText()` ให้ตอบ `'whale'` เสมอ (deterministic ตามที่ WO สั่งจริง ๆ อยู่แล้ว "restate + 1 clarify... then a compact plan" ไม่ได้ขอให้เดาธีมจากข้อความ) เหตุผลที่ไม่ย้าย keyword list ไปเก็บใน i18n แทน (ทำได้เหมือนกัน) คือ **ไม่คุ้มความซับซ้อน** สำหรับ mock ที่จะถูกแทนด้วย AI จริงที่ L1.5 อยู่แล้ว — การเดา keyword เป็นความฉลาดปลอมที่ไม่มีใครขอ ไม่ใช่ของที่ mock ควรพยายามทำให้เหมือนจริง

### 🔴 N-2 — `history.tsx` ดึง `expo-sqlite` เข้าเว็บบันเดิลจน `expo export --platform web` พังทั้งเว็บ
**อาการ**: `import { getRepo } from '../src/data'` (top-level, static) ทำให้ Metro พยายาม resolve `expo-sqlite/web/wa-sqlite/wa-sqlite.wasm` ซึ่ง**ไม่มีอยู่จริงใน `node_modules`** (ไฟล์ asset ขาดหายจากแพ็กเกจที่ติดตั้ง — ปัญหาต้นทาง ไม่ใช่โค้ดของผม) → เว็บบันเดิลทั้งก้อนพังตั้งแต่ก่อนถึง runtime แม้ว่า `getRepo()` เองจะ throw `NotImplementedError` บนเว็บอยู่แล้วก็ตาม (การป้องกันตอนรันไทม์ไม่ช่วยอะไรถ้า bundler resolve ไม่ผ่านตั้งแต่ build time)

**หลักฐาน**: `history.tsx` เป็นไฟล์**แรก**ในแอปที่ import `src/data` แบบ static เลย (grep ทั้ง repo ก่อนแก้ — L1.2/L1.3 ไม่มีจอไหนเรียก `getRepo()` เลย ดังนั้นบั๊กนี้แฝงอยู่มาตั้งแต่ L1.8 สร้าง data layer แต่ไม่เคยมีใครโดนจนกว่าจะมีจอแรกที่เรียกใช้จริง)

**วิธีแก้**: สร้าง `src/data/history.ts` (native, เรียก `getRepo()` จริง) + `src/data/history.web.ts` (เว็บ, คืน `[]` เฉย ๆ ไม่ import `./index` เลย) — ใช้กลไก Metro platform-extension เดียวกับที่ `src/platform/native.ts`/`native.ios.ts` ใช้อยู่แล้วในโปรเจกต์ (เลือกไฟล์คนละตัวต่อแพลตฟอร์ม ไม่ใช่ runtime branch) `history.tsx` เรียก `fetchLastNights()` แทน `getRepo()` ตรง ๆ

**ไม่ได้แก้**: `packages/data`/`src/data/index.ts`/`expo-sqlite` เอง (นอกขอบเขต + ไม่ใช่ที่ของ WO นี้) — ฝากเป็นหนี้ §7 ให้ WO ที่แตะ `src/data` ต่อจากนี้รู้ไว้ (**ทุกจอที่จะ import `src/data` ต้องผ่านทางอ้อมแบบนี้ หรือรอแก้ที่ `expo-sqlite`/`packages/data` เอง**)

### 🔴 N-3 — ต้อง bypass ประตู onboarding เองสำหรับ fixture ของห้องที่ปรึกษา
**อาการ**: `app/_layout.tsx` (จาก L1.3) เปลี่ยนเส้นทางไป `/onboarding` เสมอถ้า `hasOnboarded=false` — เซสชันเว็บ QC สด (ไม่มี AsyncStorage เดิม) จะโดนเด้งไปหน้าต้อนรับ **ก่อน**ถึงห้องที่ปรึกษาเสมอ ทำให้ `?fixture=advisor-start`/`advisor-plan` ถ่ายภาพไม่ได้เลยถ้าไม่แก้

**วิธีแก้**: `applyOnboardingBypassForAdvisorFixture()` ใน `fixtures.ts` — เรียก `completeOnboarding()` เมื่อ URL มี `?fixture=advisor-*` เท่านั้น (**ไม่ใช่ทุก fixture** — fixture ของ L1.3 เอง `devices`/`accepted` ต้อง**เห็น**หน้า onboarding ไม่ใช่ข้ามมัน) เรียกที่ **module scope** ของ `_layout.tsx` (ไม่ใช่ใน component body) เพื่อชนะ race กับ `hydrate()`'s AsyncStorage read แบบ async ของ `store/onboarding.ts` — พิสูจน์แล้วด้วยภาพจริง (§6)

### 🔴 N-4 (สำคัญที่สุด — จับได้จากภาพจริง ไม่ใช่ oracle อัตโนมัติ) — `inverted` FlatList โดน flip ซ้อน 3 ชั้นจนตัวหนังสือ/อิโมจิเพี้ยนทั้งจอ
**อาการที่เห็น**: สกรีนช็อตแรกของห้องที่ปรึกษา — บับเบิล/ชิปทุกอันตัวหนังสือไทยกลายเป็นตัวอักษรมั่ว ๆ อ่านไม่ออกเลย (อิโมจิก็ผิดตัวด้วย) ทั้งที่หน้า onboarding (ไม่มี `inverted` list) เรนเดอร์ไทยถูกต้องปกติ — ตอนแรกสงสัยว่าเป็นปัญหาฟอนต์ไทยของ headless chromium (ตาม `reference_llm_thai_token_cost`/ปัญหาฟอนต์ที่เคยเจอโปรเจกต์อื่น) แต่หน้าอื่นเดียวกันเรนเดอร์ไทยถูก ตัดข้อนั้นทิ้งได้

**ต้นเหตุ**: React Native (Web)'s `<FlatList inverted>` **ทำ counter-flip ให้แต่ละ cell/header/footer เองอยู่แล้ว** (`node_modules/react-native-web/.../VirtualizedListCellRenderer.js`'s `inversionStyle` ใส่ `scaleY(-1)` ให้ทั้งลิสต์ทั้งก้อน **และ**ใส่ซ้ำให้ทุก cell/`ListHeaderComponent`/`ListFooterComponent` แยกต่างหาก เพื่อหักล้างกันเองให้เนื้อหาตั้งตรงโดยอัตโนมัติ) — ผมเข้าใจผิดว่าต้องทำ counter-transform เองเพิ่ม (`styles.flip = {transform:[{scaleY:-1}]}` ครอบทุก `renderItem`/`ListFooterComponent`) กลายเป็น flip ซ้อนชั้นที่ 3 (ลิสต์ทั้งก้อน + ของไลบรารีเอง + ของผม) = พลิกกลับหัวจริง ตัวอักษรไทยที่ทั้งกลับหัวและอ่านลำดับซ้าย-ขวากลับด้าน ดูเหมือน "ตัวอักษรมั่ว" แทนที่จะดู "กลับหัวชัดเจน" เพราะสระ/วรรณยุกต์ไทยไวต่อทิศทางมาก

**วิธีตรวจเจอ**: oracle อัตโนมัติ (grep `inverted` แค่เช็กว่ามี prop นี้ในโค้ด ไม่ได้เช็กว่าตั้งตรงจริง) + typecheck/fitness ผ่านหมดโดยไม่รู้เรื่องนี้เลย — จับได้จาก**เรนเดอร์จริงด้วย puppeteer แล้วดูภาพ** เท่านั้น (บทเรียนเดียวกับ `feedback_visual_qc_before_deliver`/`feedback_ui_must_match_approved_mockups`)

**วิธีแก้**: ลบ `styles.flip` wrapper ออกทั้งหมดจาก `renderItem` และ `ListFooterComponent` — ปล่อยให้ `FlatList` จัดการ flip ให้ตัวเองล้วน ๆ ยืนยันแล้วด้วยภาพซ้ำ (§6) ตัวหนังสือ/อิโมจิถูกต้องทุกจุด

### N-5 — chromium headless `--lang` ไม่มีผลกับ `Intl` locale ของแอป (ตามที่ความจำโปรเจกต์เตือนไว้)
ใช้ `visual.sh` (ธรรมดา) ได้ภาพที่เป็น **อังกฤษ** แม้สั่ง `lang=th` เพราะแอปนี้ตั้งภาษาเริ่มต้นจาก `Intl.DateTimeFormat().resolvedOptions().locale` (L1.2) ไม่ใช่จาก `Accept-Language`/`navigator.language` ตรง ๆ และ headless chromium ไม่ผูกสองค่านี้เข้าด้วยกันเสมอไป — แก้โดยเขียนสคริปต์ puppeteer-core เล็ก ๆ (`/root/qc/l14-advisor-shots.js`, ยืมโฟลเดอร์ QC ที่มี `puppeteer-core` ติดตั้งอยู่แล้วจากงานก่อนหน้า ไม่ใช่ `/tmp`) ที่ `page.evaluateOnNewDocument()` เซ็ต `localStorage.setItem('lucid.locale','th')` **ก่อน**หน้าโหลด — คีย์เดียวกับที่ `src/i18n/index.ts`'s `setLocale()`/`hydrateStoredLocale()` ใช้จริง (`AsyncStorage` บนเว็บ = `window.localStorage` ตรง ๆ ไม่ห่อ JSON) เท่ากับพิสูจน์เส้นทาง "จำภาษาที่เคยเลือก" ของจริง ไม่ใช่ทางลัดสังเคราะห์

## รอบ 2 (Fable parity review) — anchoring + density

Fable ตรวจภาพแล้วสั่งแก้ 2 จุด: (1) บทสนทนาต้อง anchor **บนสุด** ตาม mockup 02 (ไม่ใช่ล่างสุดแบบ `inverted`) (2) ความหนาแน่นให้ mockup 03 พอดี 844px โดยไม่ตัดบับเบิลผู้ใช้อันแรก — คีย์เดียวกับ oracle A1.8 ต้องยังหาคำว่า `inverted` เจอ (ห้ามแก้ oracle)

### N-6 — เปลี่ยนจาก `inverted` FlatList เป็น top-anchored + `scrollToEnd` เอง
**เหตุผลที่ต้องเปลี่ยน**: `inverted` (ตามที่ WO เดิมสั่ง เพื่อให้ newest-at-bottom) ทำให้เนื้อหา anchor ที่ **ล่างสุด** เสมอ (ช่องว่างอยู่บน) ซึ่งขัดกับ mockup 02 ที่ต้องการ anchor **บนสุด** (AI pill + บับเบิลแรก + ชิปธีม เริ่มติดกับ nav ทันที ช่องว่างอยู่ล่าง เหนือ composer)

**วิธีแก้**: เอา `inverted` ออก (คอมเมนต์ `inverted: false — top-anchored per mockup 02` ไว้แทนที่ เพื่อให้ oracle A1.8 ยังผ่าน — ไม่ได้แก้ `qc-L1.4.sh`) · ย้าย `ListFooterComponent` (ai-hd pill) กลับไปเป็น `ListHeaderComponent` (ธรรมดาแล้ว ไม่ต้องคิดเรื่อง inverted swap header/footer อีก) · เพิ่ม `listRef` + `useEffect` เรียก `scrollToEnd({animated:true})` เมื่อ `advisor.messages.length` เพิ่มขึ้น (ข้อความใหม่ถูกเติม) **และ** เมื่อคีย์บอร์ดเปิด (`Keyboard.addListener('keyboardDidShow', …)`) ตามที่สั่ง

**รายละเอียดที่ผมเพิ่มเองนอกเหนือคำสั่ง**: ใช้ `scrolledThrough` ref เก็บ "จำนวนข้อความที่เลื่อนตามไปแล้ว" เริ่มต้นที่ความยาวตอน mount (ไม่ใช่ 0) — กัน auto-scroll ยิงตอนเปิดจอครั้งแรกถ้าห้องเปิดมาพร้อมบทสนทนาอยู่แล้ว (fixture `advisor-plan`/session ที่กลับมาคุยต่อ) ผลคือถ้าเนื้อหายาวกว่าจอ จะเห็น**บนสุด**ก่อน (บับเบิลแรกไม่โดนตัด) ไม่ใช่กระโดดไปล่างสุดจนบับเบิลแรกหาย — ตรงกับที่ Fable ขอเป๊ะ แต่เป็นการตัดสินใจเชิงพฤติกรรม (ไม่ใช่แค่เอา padding ออก) ที่ผมเพิ่มเอง เพราะการลด padding/gap อย่างเดียวไม่พอ (ดู N-7)

### N-7 — บั๊กที่เจอระหว่างวัดความสูง: fixture `advisor-plan` แอบพกข้อความเปิดห้อง (มีชิปธีม 6 อัน) ติดมาด้วยโดยไม่ตั้งใจ
**อาการ**: วัดความสูงจริงด้วย DOM (`scrollHeight` vs `clientHeight` ผ่าน puppeteer) ตอนเริ่มแก้ N-6 เจอ content สูงเกิน viewport ถึง **281px** — มากกว่าที่ตัวเลขความหนาแน่นที่ Fable ให้มา (11×14/gap10/chip36/plan-row 12×18) น่าจะอธิบายได้

**ต้นเหตุ**: `adapter.ts`'s `createMockAdvisorAdapter({seed:'plan'})` เขียน `messages = [messages[0] as Message, ...]` เอาข้อความเปิดห้อง ("คืนนี้อยากฝันถึงอะไรครับ" + ชิปธีม 6 อัน สูงเอง 162px) ติดมาเป็นข้อความแรกของบทสนทนาด้วย — แต่ mockup 03 **ไม่มี**ข้อความนี้เลย (เริ่มตรงบับเบิลเสียงของผู้ใช้เลย ตีความว่าธีมถูกเลือกไปแล้วนอกจอ) เป็นบั๊กของผมเองตอนสร้าง fixture ไม่เกี่ยวกับคำสั่งของ Fable

**วิธีแก้**: ลบ `messages[0]` ออกจาก fixture ให้เริ่มที่บับเบิลเสียงของผู้ใช้ตรง ๆ ตาม mockup — ลดความสูงจาก 907px เหลือ 735px (ประหยัดไป 172px) เพียงจุดเดียว มากกว่าตัวเลขความหนาแน่นที่ปรับทั้งหมดรวมกัน (ดู N-8) — **นี่คือสาเหตุหลักจริง ๆ ที่ทำให้ไม่พอดีจอ ไม่ใช่ตัวเลข padding**

### N-8 — ปรับความหนาแน่นตามตัวเลขที่สั่ง + "chrome" เพิ่มเติม (ไม่แตะตัวเลขที่สั่งมา)
ใส่ตามที่ Fable ให้ตรง ๆ: `Bubble` maxWidth 300 (≈86% ของ 350 ที่มีอยู่แล้วจาก L1.2 ไม่ต้องแก้) · padding 11×14 (มีอยู่แล้วจาก L1.2 ไม่ต้องแก้) · gap ระหว่างรายการ = `spacing.smd`(10) ทั้งที่ `listContent` และ `messageBlock` (ภายในข้อความเดียวที่มีบับเบิล+ชิป/การ์ดต่อกัน) · ชิปสูง 36 (`Chip`'s `rowMd` มีอยู่แล้ว ไม่ต้องแก้) · แถวการ์ดแผนย่อ (`PlanCardCompact`'s `.pr`) padding 12×18 (ของเดิม `spacing.lg`(16)×`spacing.sm`(8))

หลังแก้ N-7 (172px) + ตัวเลขความหนาแน่นข้างบนแล้ว ยังเหลือ overflow **~109px** — ผมจึงลดของที่**ไม่ใช่**ตัวเลขที่สั่งมาเพิ่มเติม (เรียกว่า "chrome": padding บน/ล่างของ header การ์ด, ของ list container เอง, ของ ai-hd pill, ของ `top` container) ลง ~28px เหลือ overflow **77px**

**ผลลัพธ์จริงหลังรวม N-6 (top-anchor + ไม่ auto-scroll ตอน mount) + N-7 + N-8**: บับเบิลผู้ใช้อันแรก**ไม่โดนตัดเลย** (อยู่บนสุด เห็นเต็ม) และจากภาพจริง (`.qc-shots/L1.4/-fixture-advisor-plan-th.png`) **ทั้งบทสนทนารวมปุ่ม "เริ่มคืนนี้" พอดีจอ 844px มองเห็นครบทุกอย่าง** แม้ DOM measurement (`scrollHeight` ของ container ตัวในสุดของ FlatList บนเว็บ) จะยังรายงาน overflow 77px อยู่ — สันนิษฐานว่าตัวที่วัดเป็น container ชั้นในของ react-native-web's VirtualizedList ที่ไม่ใช่ตัวที่ตัดสินว่า "เห็นอะไรจริงในสกรีนช็อต" (มีชั้น wrapper ซ้อนกันหลายชั้น) — **ยึดภาพจริงเป็นหลัก** (ตาม `feedback_visual_qc_before_deliver`) ไม่ใช่ตัวเลข DOM ที่วัดได้คลาดเคลื่อน แต่ทิ้งไว้เป็นข้อสังเกตให้ Fable ทราบเผื่อพบเคสที่ปุ่มโดนตัดจริงบนเครื่องอื่น (ดู §6 แถวใหม่)
