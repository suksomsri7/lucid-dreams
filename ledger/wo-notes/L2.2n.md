## 2. รูปแบบข้อความบนสาย (สัญญาที่ห้ามแตกต่างกันสองฝั่ง)

### 2.1 นาฬิกา → มือถือ
| ข้อความ | รูปแบบ | ช่องทาง |
|---|---|---|
| epoch | `["t": Int, "hrMean": Double?, "hrSd": Double?, "motion": Double?, "battery": Double?]` — ฟิลด์ที่ไม่มีค่า **ไม่ใส่คีย์** (ไม่ใช่ `null`) | `sendMessage` ถ้า reachable ไม่งั้น `transferUserInfo` (คิว FIFO) |
| หยุด | `["command": "stop"]` | `sendMessage` เท่านั้น — **ไม่เข้าคิว** โดยตั้งใจ: "stop" ที่มาถึงอีกชั่วโมงหนึ่งจะไปหยุดคืนใหม่ที่ผู้ใช้เพิ่งเริ่ม |

### 2.2 มือถือ → นาฬิกา
| ข้อความ | รูปแบบ | ช่องทาง |
|---|---|---|
| คำสั่ง | `["command": "start" \| "stop"]` | `sendMessage` (ถ้าไม่ reachable = ไม่ส่ง ไม่คิว) |
| สถานะสด | `["status": ["pRem": Double?, "cuesPlayed": Int, "cuesPlanned": Int]]` | `updateApplicationContext` — ค่าล่าสุดชนะ รอดแม้นาฬิกาหลับ (คิวจะเล่นเปอร์เซ็นต์เก่าย้อนหลัง) |
| สตรีค | `["streakNights": Int]` | `updateApplicationContext` (merge กับ context เดิม ไม่ทับกัน) |

### 2.3 native → JS (event ของ `LucidWatchLink`)
`epoch` = payload ดิบตามข้อ 2.1 · `status` = `{paired, installed, reachable, model}` (`model` เป็น `null` เสมอ — WCSession ไม่บอกรุ่นนาฬิกา) · `command` = `{type:"stop"}`
> ชื่อ event เปลี่ยนจาก stub ของ L1.1 (`onEpoch`/`onStatus`/`onCommand`) เป็น `epoch`/`status`/`command` ตามที่ใบงานกำหนด — ฟังก์ชันที่ export ออกไปยังชื่อ `on*` เหมือนเดิม **ไม่มี caller ไหนต้องแก้**

### 2.4 App Group + Live Activity
- App Group `group.app.dreaming` — ใช้ **ในเครื่องเดียวกัน** เท่านั้น (คอนเทนเนอร์ของ iPhone กับของ Watch เป็นคนละที่ ไม่ sync กัน) บนนาฬิกาใช้ส่งสตรีคจากแอปนาฬิกา → complication คีย์ `streak.nights` / `streak.updatedAt`
- `DreamingNightAttributes`: คงที่ `theme` (ธีมล็อกตั้งแต่เข้านอน) · `ContentState {status, cuesPlayed, cuesPlanned}`

## 3. การตัดสินใจที่ไม่ได้เขียนตรง ๆ ในใบงาน

1. **`DreamingNightAttributes.swift` มี 2 ก๊อปปี้** (`targets/live-activity/` กับ `modules/lucid-live-activity/ios/`) — ฝั่งที่เรียก `Activity.request` อยู่ใน **pod** ส่วนฝั่งที่วาดอยู่ใน **app extension** เป็นคนละ Swift module และ apple-targets ไม่สร้าง shared framework ให้ · ActivityKit จับคู่ด้วย **ชื่อ type** ไม่ใช่ module (นี่คือผลลัพธ์เดียวกับที่คำแนะนำของ Apple "ใส่ไฟล์เดียวกันเข้าทั้งสอง target" ให้) · ทั้งสองไฟล์ต่างกันแค่ย่อหน้าคอมเมนต์ — R1 ต้อง diff ก่อนแก้ฟิลด์ใด ๆ
2. **`IosLiveStatus` เป็นคนส่งสถานะไปนาฬิกาด้วย** ไม่ใช่ `WatchSensorSource` — DESIGN §3.4 จัดล็อกสกรีนกับหน้าปัดนาฬิกาไว้กลุ่มเดียวกัน ("นอกแอป") ทั้งคู่โชว์ข้อมูลชุดเดียวกันซึ่ง `LiveStatusContent` มีครบอยู่แล้ว · ทางเลือกอื่นคือให้ `session.ts` เรียกสองที่ ซึ่งแปลว่ามีสองแหล่งที่เลขจะเพี้ยนจากกันได้
3. **ใช้ `normalizeEpochs` ของ engine แทนกฎที่เขียนเองซ้ำ** — `replay.ts` ใช้ตัวนี้กับคืนที่บันทึกไว้ ถ้าฝั่งสดใช้กฎที่ก๊อปมา คืนสดกับคืน replay จะถูกตัดสินคนละมาตรฐาน (บทเรียน `reference_one_status_two_meanings`) · ตามด้วย `SensorEpochSchema` เพราะ normalize ไม่ได้ดู battery > 1 / motion ติดลบ / hrSd เพี้ยน
4. **native module เก็บ epoch ที่มาถึงก่อน JS จะ subscribe** (backlog 200 อัน ≈ 100 นาที) แล้ว flush ตอน `activate()` — watchOS ส่งคิวย้อนหลังทันทีที่มือถือตื่น ซึ่งอาจมาก่อน `startNightSession()` จะ subscribe · `WatchSensorSource.start()` subscribe ก่อนเรียก `activate()` อยู่แล้ว ลำดับจึงพอดี
5. **`LucidLiveActivityModule` ไม่เก็บ state ของตัวเองเลย** ใช้ `Activity.activities` ของระบบเป็นแหล่งจริง — activity อยู่ต่อแม้แอปถูกฆ่า ถ้าเก็บ `var activity` ไว้เอง คืนที่แอปถูกฆ่ากลางคันจะเหลือการ์ดที่ผู้ใช้ปิดไม่ได้
6. **`end()` ใช้ `.immediate`** ไม่ใช่ `.default` (ซึ่งทิ้งการ์ดไว้บนล็อกสกรีนได้ถึง 4 ชั่วโมงหลังคืนจบ)
7. **`staleDate: nil`** — คืนหนึ่งอยู่เงียบ ๆ ได้ 3 ชั่วโมงตามกติกา guard (DESIGN §5.3) ถ้าตั้ง stale date การ์ดที่ถูกต้องจะกลายเป็นสีเทากลางดึก
8. **แตะ `src/night/session.ts` 4 จุด** ทั้งที่อยู่นอกรายการ "Touch" — deliverable 3 สั่งให้ deep link ไปจบที่ `session.userStop()` ซึ่งทำจากในโฟลเดอร์ `platform/` อย่างเดียวไม่ได้ (ต้องมีคนรับ event) · เพิ่ม `title:` 2 จุด, subscribe + unsubscribe อีก 2 จุด, และ helper `themeTitle()` 1 ตัว

## 4. DND / Focus — ทำไม `dndAllowsAppAudio()` ยังคืน `true`

อ่านเต็มในหัวไฟล์ `src/platform/dnd.ts` สรุปหลักฐาน 3 ข้อ:

1. **iOS ไม่มี API ที่ตอบว่า "เสียงของแอปฉันถูกปิดอยู่ไหม"** — `UNUserNotificationCenter` ตอบเรื่อง *การแจ้งเตือน* · `INFocusStatusCenter` ตอบว่าผู้ใช้อยู่ใน Focus ไหม · ไม่มีอันไหนแปลว่า playback เงียบ
2. **Focus ไม่ได้ปิดเสียงเรา** — คืนเล่นผ่าน `AVAudioSession` category `playback` + `playsInSilentMode` (ดู `IosAudioPlayer.configureSession`) Sleep Focus ปิดการแจ้งเตือนกับสายเข้า ไม่ใช่ session นี้ · แปลว่าถ้าเอา "อยู่ใน Focus" มาเป็นด่าน **ทุกคืนจะถูกบล็อก** ด้วยข้อความ `ready.blocker.DND_BLOCKS` ("ปิดห้ามรบกวนก่อน") เพราะตอนเข้านอนแทบทุกคนอยู่ใน Sleep Focus — และข้อความนั้นก็ไม่จริงด้วย
3. **entitlement `com.apple.developer.focus-status` ยังไม่ใส่** เพราะต้องเปิด capability ที่ App ID ก่อน ซึ่งยังไม่มีบัญชี Apple (APP-RUN §0.3 ข้อ 2) · ใส่ entitlement ที่ profile ไม่มี = บิลด์ตกเงียบ ๆ (`reference_watch_target_entitlements`)

ผลลัพธ์: โมดูลอ่านได้จริงและรายงาน `known:false` ตามที่ใบงานกำหนดไว้เป็น fallback · สวิตช์ `TREAT_FOCUS_AS_BLOCKING` ใน `dnd.ts` คือจุดเดียวที่ต้องพลิกถ้า Fable ตัดสินใจเป็นอย่างอื่น (ต้องพลิกพร้อมใส่ entitlement)
ค่าที่ทำนาย "กระซิบแล้วไม่ได้ยิน" ได้จริง (`outputVolume == 0`, `otherAudioPlaying`) เปิดไว้ที่ `readAudioEnvironment()` แต่ **จงใจไม่ผูกเข้าด่าน** เพราะข้อความของด่านพูดถึงห้ามรบกวน ถ้าเอาไปใช้จะกลายเป็น error ที่โทษผิดเรื่อง (`feedback_error_must_not_blame_user`)

## 6. 🔴 สิ่งที่ R1 ต้องตรวจบนเครื่องจริง (เรียงตามความเสี่ยง)

1. **คอมไพล์ Swift ทั้ง 3 target + 4 pod** — ยังไม่เคยผ่าน swiftc เลย จุดที่เสี่ยงที่สุด:
   - `AsyncFunction` แบบ async closure ใน `LucidLiveActivityModule` (`await activity.update`) กับกฎ Sendable ของ Swift 6 — podspec ตั้ง `swift_version = 5.9` จึงควรเป็นแค่ warning ถ้าเป็น **error** ให้เปลี่ยนเป็นรูปแบบ `Promise` + `Task { }` (แบบเดียวกับ `lucid-health`)
   - `@MainActor` บน `WorkoutManager` + delegate ของ HealthKit (หนี้เดิมจาก L1.1 ยังไม่หาย)
   - `String(localized:)` ต้องเป็น string literal ทุกจุด (ตรวจแล้วด้วยตา ไม่มีตัวแปร)
2. **Live Activity ขึ้นจริงไหม** — ถ้าไม่ขึ้น สาเหตุอันดับหนึ่งคือ `DreamingNightAttributes` สองก๊อปปี้ไม่ตรงกัน (ต้อง diff) อันดับสองคือ `NSSupportsLiveActivities` ไม่ติดใน Info.plist ของแอป
3. **ปุ่ม "หยุด" บนล็อกสกรีน** → ต้องเปิดแอปมาที่จอกลางคืนแล้ว**คืนจบจริง** (ไม่ใช่แค่เปิดแอป) · แตะ*ตัวการ์ด* ต้องเปิดแอปเฉย ๆ ไม่หยุดคืน
4. **complication**: เพิ่มลงหน้าปัดได้ · ตอนแรกต้องเห็น **"—"** ไม่ใช่ "0" · ยังไม่มีใครส่งสตรีคมา (หนี้ §8 ข้อ 1)
5. **entitlement/App Group ต้องสร้างที่ developer portal ก่อน** ทั้ง `group.app.dreaming` และ capability HealthKit — ไม่มี = บิลด์ตกเงียบ
6. **นอนจริง 1 คืน**: epoch มาถึงมือถือกี่ % · ปุ่มกดค้าง 1 วิ บนนาฬิกาหยุดคืนทั้งสองเครื่อง · แบตนาฬิกาตอนเช้า · `WKCompanionAppBundleIdentifier` ที่แก้แล้วทำให้จับคู่ติดจริง
7. **HealthKit เช้าวันรุ่งขึ้น**: `readSleepStages` คืนสเตจจริงไหม · ถ้าได้ `[]` ให้ดูว่าเป็นเพราะไม่มีข้อมูลหรือถูกปฏิเสธ (HealthKit ไม่บอก — §7 ข้อ 3)
8. **ภาษาไทยบนนาฬิกา/complication/Live Activity** — สลับภาษาเครื่องเป็นไทยแล้วดูว่าขึ้นไทยจริง (xcstrings ถูกคอมไพล์เข้า bundle ไหม)
9. **หูซ้าย/ขวา** — ฟังว่าเสียงออกข้างเดียวจริง และไม่มี event `PAN_SOURCE_MISMATCH` ใน diagnostics

## 7. ข้อขัดแย้ง / เรื่องที่ต้องให้ Fable ตัดสิน

1. **`scripts/qc-L1.1.sh` ข้อ S4.7 ตกแล้วโดยตั้งใจ** — ข้อสอบ grep หาคำว่า `Lucid Dream` ใน `app.config.ts` แต่เจ้าของสั่งเปลี่ยนชื่อเป็น "Dreaming" (คำสั่งกลางงานของใบนี้) ผมห้ามแก้ `scripts/qc-*.sh` → **Fable ต้องแก้บรรทัดนั้นเป็น `Dreaming`** ไม่งั้นชุดข้อสอบจะค้างที่ 40/41 ตลอดไป
2. **หนี้ L1.3 (InfoPlist.strings ไม่เข้า pbxproj) ปิดแล้ว — ต่างจากที่ L1.3 ตัดสินใจไว้** L1.3 เลี่ยงเพราะ "pbxproj surgery เสี่ยงและไม่มี Mac ทดสอบ" · ตอนนี้ไม่ใช่ surgery แล้ว: ใช้ `IOSConfig.XcodeUtils.addResourceFileToGroup` ซึ่งเป็น helper **ตัวเดียวกับที่ `IOSConfig.Locales.withLocales` ของ Expo ใช้กับไฟล์ชนิดนี้ path แบบเดียวกันเป๊ะ** (`<project>/Supporting/<lang>.lproj/InfoPlist.strings`) · ไม่ย้ายไปใช้ฟิลด์ `locales` ของ Expo ตรง ๆ เพราะฟิลด์นั้นอ่าน **JSON** แต่ `qc-L1.3.sh` (O4.5) เช็กว่าต้องมี `apps/mobile/locales/th/InfoPlist.strings` — ถ้า Fable อยากได้ทางมาตรฐานเต็มรูปแบบ ต้องแก้ข้อสอบข้อนั้นด้วย
3. **`requestAuthorization()` ของ HealthKit ตอบ "ถามแล้ว" ไม่ใช่ "ได้สิทธิ์"** — HealthKit **จงใจ**ไม่บอกว่าผู้ใช้ปฏิเสธการอ่าน (query ที่ถูกปฏิเสธคืน array ว่าง เหมือนกับ "ไม่มีข้อมูล") ใบงานเขียนว่า "Returns true only if access was actually granted" ซึ่ง **ทำไม่ได้จริง** · ใช้ `getRequestStatusForAuthorization` = `.unnecessary` แทน (แปลว่าไม่เหลืออะไรให้ถามแล้ว) · ปลอดภัยเพราะ `src/health/appleSleep.ts` ปฏิบัติกับ "ว่าง" เหมือน "ถูกปฏิเสธ" อยู่แล้ว
4. **สเตจ `IN_BED` ไม่ใช่ `INBED`** — ใบงานเขียน `'INBED'` แต่ `SleepStage` ใน `types.ts` (ของ L1.3) เป็น `'IN_BED'` และ `src/health/appleSleep.ts` ใช้ตัวนั้นอยู่ ผมให้ native คืน `IN_BED` เพื่อไม่ต้องมีชั้นแปลงเพิ่ม
5. **`asleepUnspecified` ถูกทิ้ง ไม่แปลงเป็น CORE** — "หลับอยู่ แต่ไม่รู้สเตจ" แปลงเป็น CORE ไม่ได้โดยไม่แต่งข้อมูล และ CORE แปลว่า "ไม่ใช่ REM" ซึ่งจะนับเป็นหลักฐานว่าเราทายผิด · ทิ้งไป = นาทีนั้นไม่เข้าการเปรียบเทียบ ซึ่งซื่อสัตย์กว่า
6. **deep link เป็น `dreaming://night?stop=1` ไม่ใช่ `dreaming://stop`** — `apps/mobile/app/` ไม่มี route ชื่อ `stop` (ตรวจแล้ว: `(tabs)`, `night`, `plan/*`, `report/[id]`, `onboarding/*`, `history`, `diagnostics`, `dev/ui`) และ expo-router ตอบ path ที่ไม่ตรงด้วยจอ "Unmatched Route" → ปุ่มหยุดจะกลายเป็นจอ error ทับจอกลางคืน · ตัวรับใน `IosLiveStatus.isStopLink()` รับ `dreaming://stop` ด้วย ถ้าใบหน้าเพิ่ม route นั้นทีหลังไม่ต้องแก้ widget
7. **privacy manifest ไม่ประกาศ health/audio เป็น "collected data"** ทั้งที่ใบงานสั่ง — Apple นิยาม "collected" ว่า **ส่งออกนอกเครื่อง** · ชีพจร/สเตจการนอน/ไฟล์เสียง ไม่เคยออกจากเครื่อง (APP-RUN §0.5 S4 "ไม่ส่งเสียงขึ้นเซิร์ฟเวอร์เลย") ประกาศไปจะเป็นคำแถลงที่ **ไม่จริง** · ที่ประกาศคือสิ่งที่ส่งจริง: ข้อความฝัน (`OtherUserContent`, เมื่อ consentAi) และ device token (`DeviceID`) · required-reason API ตามใบงาน: UserDefaults `CA92.1` (App Group ไม่ใช่ container ธรรมดา) + FileTimestamp `C617.1`
8. **โมดูลที่ 4 (`lucid-focus`) ไม่ได้อยู่ในรายการ 3 โมดูลของใบงาน** — แยกออกมาเพราะเป็นตัวเดียวที่ต้องใช้ entitlement ที่เราจงใจไม่ใส่ ถ้ายัดรวมกับโมดูลอื่นจะลากความเสี่ยงนั้นไปทั้งก้อน
