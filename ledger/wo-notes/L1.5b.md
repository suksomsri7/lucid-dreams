## 1. อะแดปเตอร์ fal — สิ่งที่วิ่งบนสาย

```http
POST https://fal.run/fal-ai/elevenlabs/tts/eleven-v3
Authorization: Key <FAL_KEY>            ← สคีม "Key" ไม่ใช่ "Bearer" (Bearer = 401)
content-type: application/json

{ "text": "[whispers] คุณกำลังฝันอยู่…", "voice": "Sarah", "stability": 0.6, "language_code": "th" }
```

```json
{ "audio": { "url": "https://v3b.fal.media/files/b/…/output.mp3",
             "content_type": "audio/mpeg", "file_size": 20942 }, "timestamps": null }
```

แล้วอะแดปเตอร์ **โหลด url นั้นอีกหนึ่งรอบ** (fal คืนลิงก์ ไม่คืนไบต์) → `{ buffer, contentType }`

- **เสียงกระซิบเกิดจากแท็กในข้อความ ไม่ใช่พารามิเตอร์** — `eleven-v3` รับการกำกับเป็น audio tag ⇒ `[whispers] ` นำหน้าประโยค · ไม่ต้องใช้ SSML แบบ Azure (ตัวเลือก (ง) ใน L1.5 D1 จึงตกไป)
- **สองรอบอยู่ใน deadline เดียว** (`TTS_TIMEOUT_MS`, ค่าเริ่มต้น 30 วิ) — คนที่รอ JSON มา 30 วิแล้วไม่เหลือความอดทนให้ไฟล์เสียง
- **ไม่เชื่อ `content-type` ของ vendor** — ดมคอนเทนเนอร์เอง (`ID3` / frame sync `0xFF 0xEx` / `RIFF…WAVE`) ⇒ หน้า HTML ที่ส่งมาพร้อมหัวข้อ `audio/mpeg` ไม่มีวันถูกแคชเป็นเสียงกระซิบของผู้ใช้
- **ไม่อ่าน body ของ error** — body ของ fal อาจสะท้อนประโยคกลับมา · เก็บแค่ status
- เพดาน 5 MB (`FAL_MAX_AUDIO_BYTES`): ประโยค 120 ตัวอักษร ≈ 40 KB ⇒ อะไรที่ใหญ่กว่านี้คือ url ผิด ไม่ใช่ประโยคของเรา

| รหัสผิดพลาด (`TtsError.code`) | เมื่อไร |
|---|---|
| `FAL_HTTP_<status>` | fal ตอบไม่ใช่ 2xx (401 = กุญแจ · 422 = body · 429 = ยิงถี่ · 5xx = เหตุที่ฝั่งเขา) หรือโหลดไฟล์ไม่ได้ |
| `FAL_NO_URL` | 200 แต่ไม่มี `audio.url`/`url` (หรือตอบไม่ใช่ JSON) — ไม่มีการโหลดตามมา |
| `FAL_BAD_AUDIO` | ไบต์ที่โหลดได้ไม่ใช่เสียง หรือใหญ่เกินเพดาน |
| `FAL_TIMEOUT` | ครบ deadline (abort จริง ข้อสอบ A8 ตรวจว่า abort ถูกยิง) |
| `FAL_NETWORK` | DNS/TLS/คอนเนกชันขาด |

เซิร์ฟเวอร์แปลงเป็น `502 PROVIDER_UNAVAILABLE` (ยิงไม่ถึง/ไม่สำเร็จ) หรือ `502 PROVIDER_SCHEMA` (ได้ของที่ไม่ใช่เสียง) — log เก็บ `code` ไม่เก็บข้อความ

## 2. `POST /ai/anchor` — ลายน้ำทั้งไฟล์

```http
POST /ai/anchor          Authorization: Bearer <device token>
{ "seed": "<seed ของผู้ใช้ ≤64 ตัว>", "lang": "th" | "en", "voice": "Sarah"? }

200 audio/mpeg
x-cache: MISS | HIT
x-anchor-hash: 526246efaf8a6dfb          ← = makeSignature(seed, lang).hash
x-anchor-notes: 62,66,69,71              ← โน้ต MIDI ของลายเสียง (คนละภาษาได้โน้ตเดียวกัน)
cache-control: private, max-age=86400
```

ลำดับงาน — เรียงตามราคา ไม่ใช่ตามความสวย:

1. **ตรวจ ffmpeg ก่อน** (`FFMPEG_PATH` → `/usr/bin/ffmpeg` → `/usr/local/bin/ffmpeg`) · ไม่มี = `501 NOT_CONFIGURED` + `detail` · เป็นของฟรี จึงตรวจก่อนของที่เสียเงิน (ข้อสอบ B8 ยืนยันว่า vendor ไม่ถูกเรียกเลย)
2. **ลายเสียงสังเคราะห์ใหม่ทุกครั้ง ไม่แคช** — `makeSignature(seed, lang)` + `renderSignaturePcm(sig, 48000)` เป็นคณิตศาสตร์ล้วน เร็วกว่าไปหาในแคช และเป็นไบต์เดียวกันกับที่มือถือคำนวณได้เอง
3. **เสียงกระซิบมาจากแคชร่วม** — คีย์เดียวกับ `/ai/tts` ⇒ ผู้ใช้คนที่สองในภาษานั้น **ไม่เสียเงินเลย** (พิสูจน์ใน §5: ขอ `/ai/tts` หลังจาก `/ai/anchor` ได้ `x-cache: HIT`)
4. **ผสม** → แคชผลด้วยคีย์ที่รวมทุกอย่างที่เปลี่ยนไบต์ได้
5. ผลลัพธ์ต้องดมได้ว่าเป็น mp3 ไม่งั้น `500 MIX_FAILED` (ffmpeg ล้ม/หมดเวลา ก็ 500 — เป็นเครื่องมือของเราเอง ไม่ใช่ความผิดของไคลเอนต์หรือ vendor)

ด่านเหมือน `/ai/*` อื่นทุกข้อ: Bearer → zod → rate limit (`dev:<id>:ai` 60/ชม. แบบเลื่อน) · body ≤ 32 KB (ด่านกลางของแอป)

### ท่า ffmpeg (อ่านครั้งเดียวจบ)

```
[0:a] aformat=fltp:48000:mono, volume=0.8            → [a]    ลายเสียง เบาลงเหลือ 0.8
[1:a] aformat=fltp:48000:mono, adelay=1700:all=1     → [b]    กระซิบ เลื่อนไป 1.7 วิ
[a][b] amix=inputs=2:duration=longest:dropout_transition=0:normalize=0
→ libmp3lame -b:a 128k -ar 48000 -ac 1  (-map_metadata -1)
```

- `normalize=0` **คือหัวใจ** — ค่าเริ่มต้นของ `amix` หารทุกอินพุตด้วยจำนวนอินพุต ⇒ ลายเสียงที่เราตั้งไว้ 0.8 จะถูกหารเป็น 0.4 เงียบ ๆ
- `dropout_transition=0` กันไม่ให้ amix ค่อย ๆ ดันลายเสียงกลับขึ้นตอนกระซิบจบ
- `-map_metadata -1` + ไม่มีแท็กเวลา ⇒ **ไบต์เดียวกันทุกครั้ง** (ข้อสอบ B4: เซิร์ฟเวอร์คนละตัว seed เดียวกัน sha256 ตรงกัน)
- ไฟล์ชั่วคราวอยู่ใน `os.tmpdir()/lucid-anchor-*` และถูกลบใน `finally` เสมอ (systemd ให้ `/tmp` ส่วนตัว · เครื่องนี้เคยดิสก์เต็มเพราะของชั่วคราวไม่ถูกลบ)

### คีย์แคช (ทั้งสองอยู่ในตาราง `tts_cache` เดิม)

| อะไร | คีย์ |
|---|---|
| เสียงกระซิบ | `sha256("<ประโยค>|<ภาษา>|<เสียง>")` — `<เสียง>` = `whisper` (สไตล์) ถ้า body ไม่ระบุชื่อเสียง ⇒ **ใช้ร่วมกับ `/ai/tts`** · ระบุชื่อเสียงมา = แถวของตัวเอง |
| ลายน้ำที่ผสมแล้ว | `sha256("anchor|1700|0.8|<seed>|<ภาษา>|<เสียง>|<hash ลายเสียง>|<sha256 ของไฟล์กระซิบ>")` |

`1700|0.8` (ค่าหน่วงและเกนของการผสม) อยู่ในคีย์ **เพิ่มจากที่ใบสั่งเขียนไว้** โดยเจตนา: วันที่เจ้าของฟังแล้วสั่ง "ให้กระซิบช้าอีกครึ่งวิ" ไฟล์เก่าจะ *หาไม่เจอ* แทนที่จะถูกเสิร์ฟต่อไปตลอดชีพ · คำนำหน้า `anchor|` แยก namespace จากแถวของ `/ai/tts`

## 3. สัญญา `TtsProvider` ที่ต้องกว้างขึ้น 1 นิ้ว

ใบสั่งบอกว่า "implement สัญญาเดิม" **และ** "คืน `{buffer, contentType:'audio/mpeg'}`" — สองข้อนี้ขัดกัน เพราะสัญญาเดิมในข้อสอบ L1.5 คือ `(req) => Promise<Buffer>` (`test/L1.5-api.test.ts` บรรทัดหัวไฟล์ + ตัวปลอมของข้อสอบคืน `Buffer`)

แก้ด้วยการ **ขยายเป็นยูเนียน**: `TtsProvider = (req) => Promise<Buffer | TtsAudio>` — ของเดิมยังถูก (Buffer assignable) ข้อสอบ 11 ข้อผ่านโดยไม่แตะ และอะแดปเตอร์จริงบอกคอนเทนเนอร์ที่มันโหลดมาได้ · `normalizeTtsAudio()` เป็นที่เดียวที่รู้เรื่องยูเนียนนี้ และมัน **ดมไบต์ทับคำกล่าวอ้างของอะแดปเตอร์เสมอ**

`TtsRequest.voiceName?` เพิ่มเข้ามาเพื่อส่ง "ชื่อเสียงของ vendor" (Sarah/Laura/Charlotte) ซึ่งเป็นของคนละชั้นกับ `voice: 'whisper'` ที่เป็น *สไตล์*

- log ตรวจแล้ว **ไม่มีกุญแจ ไม่มีประโยค ไม่มีแท็ก `[whispers]`** — มีแค่ `keyLen` · `textLen` · `bytes` · `ms` · `status`

- ไฟล์ที่ได้เก็บไว้ให้เจ้าของฟัง **นอก repo**: `/root/.lucid/tts-l15b/anchor-th.mp3` · `anchor-en.mp3` · `anchor-th-other.mp3` (seed คนละคน) · `whisper-th.mp3` · `whisper-en.mp3` · ตัวอย่าง 3 เสียงของ Fable ยังอยู่ที่ `/root/.lucid/tts/`

## 8. ข้อแย้ง / จุดที่ทำต่างจากใบสั่ง (พร้อมเหตุผล)

1. **`{buffer, contentType}` vs สัญญาเดิม `Promise<Buffer>`** — ใบสั่งขอทั้งสองอย่างซึ่งขัดกัน · แก้ด้วยยูเนียน `Buffer | TtsAudio` (ข้อสอบ L1.5 ไม่ถูกแตะและยังผ่าน) — §3
2. **ตรวจ ffmpeg ก่อนเรียก TTS** (ใบสั่งวาง 501 ของ ffmpeg ไว้ท้ายสุด) — ของฟรีต้องล้มก่อนของที่เสียเงิน · **ผลข้างเคียงที่ยอมรับ**: เครื่องที่ไม่มี ffmpeg จะตอบ 501 แม้ไฟล์นั้นอยู่ในแคชแล้ว (คีย์แคชต้องใช้ hash ของไฟล์กระซิบจึงจะรู้ว่ามีของ) — ถ้า Fable อยากให้แคชชนะ ต้องถอด `ttsHash` ออกจากคีย์ ซึ่งแลกด้วยการเสิร์ฟไฟล์เก่าหลังเปลี่ยนเสียง — เลือกแบบปลอดภัยกว่า
3. **คีย์แคชมี `1700|0.8` เพิ่มเข้ามา** — เหตุผลใน §2 (กันไฟล์ค้างตลอดชีพเมื่อจูนค่า) · ยังเป็น sha256 ของ `seed|lang|voice|sigHash|ttsHash` ตามที่สั่ง แค่มีคำนำหน้าที่บอกเวอร์ชันของการผสม
4. **`voice` ใน body ขัดกับ §2 ข้อ 3 ("ไม่มีตัวเลือกเสียง")** — เก็บไว้ตามใบสั่ง แต่ถือเป็น **เครื่องมือของเจ้าของสำหรับเทียบเสียง** ไม่ใช่ฟีเจอร์ของผู้ใช้: README เขียนกำกับไว้ · แอปต้องไม่ส่งฟิลด์นี้ · ถ้าอยากปิดตายให้ลบออกจาก zod 1 บรรทัด
5. **ผลลัพธ์เป็น 48 kHz ทั้งที่ fal ส่ง 44.1 kHz** — ffmpeg รีแซมเปิลกระซิบขึ้น 48k เพราะลายเสียงเป็น 48k โดยธรรมชาติ (engine) · รีแซมเปิลเสียงพูดเสียหายน้อยกว่ารีแซมเปิลโทนบริสุทธิ์ที่ต้องตรงกับที่มือถือสังเคราะห์
6. **ffmpeg ล้ม = 500 ไม่ใช่ 502** — 502 สงวนไว้สำหรับ "ปลายทางที่เราไม่ได้คุม" · ffmpeg เป็นเครื่องมือของเราเอง ⇒ `500 MIX_FAILED`
