## 2. เส้นทาง BLE + การตัดสินใจที่ไม่ได้เขียนตรง ๆ ใน WO

**1) hub ต้องส่ง epoch ทุก 30 วิ "แม้ไม่มีใครพูด" — นี่คือสิ่งที่ทำให้โหมดตัวจับเวลาเกิดได้จริง**
`NightController` เดินด้วย epoch ไม่ใช่ด้วยนาฬิกาแขวนผนัง และตัวนับ `sensorLostEpochs` จะขยับก็ต่อเมื่อมี epoch ที่ `hrMean == null && motion == null` ป้อนเข้าไป (20 ใบ = 10 นาที → `timerFallback`) **ของเดิม** `session.ts` ต่อสายจาก `watchSensorSource.onEpoch` ตรง ๆ ⇒ คืนที่ไม่มีนาฬิกาเลย = ไม่มี epoch สักใบ = คอนโทรลเลอร์ค้างอยู่ที่วินาทีแรกทั้งคืน ไม่ถึง onset ไม่ fallback ไม่กระซิบ hub ตัวนี้จึงปิด epoch ตามตารางเสมอ และเมื่อไม่มีใครส่งอะไรเข้ามาเลยจะปล่อย epoch ว่าง `source:'TIMER'` ออกไป — **ข้อนี้คือจุดที่ deliverable "fallback to timer mode … the controller already supports it" เป็นจริง**

**2) sample กับ epoch — แหล่งละทางเดียว ไม่นับซ้ำ**
สายคาดอกพูดทุกจังหวะหัวใจพร้อม RR ⇒ ถ้าบีบเป็น epoch ตั้งแต่ต้นทาง HRV จะหายไปทั้งก้อน จึงเพิ่ม `onSample` (interface ใหม่ `SampleSensorSource`) ให้ engine hub เห็นหลักฐานรายเม็ด ส่วนนาฬิกาที่ผลิตแต่ epoch ต่อผ่าน `onEpoch` แล้วแปลงเป็น sample ใบเดียว · hub สมัครสมาชิกให้แหล่งละทางเท่านั้น
**ผลข้างเคียงที่ต้องรู้**: epoch ของนาฬิกา = 1 sample ส่วนสายคาด ≈ 30 sample ⇒ คืนที่ใส่ทั้งคู่ `hrMean` จะเอนไปทางสายคาด นี่คือกติกาของ engine เอง ("weighting by sample count is weighting by evidence") และสายคาดคือเครื่องมือที่แม่นกว่า ทิศทางจึงถูก — แต่มัน **เอน** ไม่ใช่เฉลี่ยกลาง ๆ (ดูหนี้ D-3)

**3) dedupe กับสายคาดที่เต้นเกิน 120 ครั้ง/นาที**
engine hub รับ 1 ค่า/(แหล่ง, วินาที) — กติกา S8 ที่กันสายคาดหลุดแล้วต่อใหม่ replay บัฟเฟอร์ แต่สายคาดที่ >120 bpm ส่ง 2 ครั้งในวินาทีเดียว *จริง ๆ* ถ้าทิ้งใบที่สองก็คือทิ้ง RR ของจังหวะจริงไปด้วย จึงใช้ "วินาทีเดินหน้าอย่างเดียว" (`nextSampleSecond()`): ค่าที่ชนวินาทีเดิมถูกวางที่วินาทีว่างถัดไป — คลาดต่ำกว่า 1 วินาที (สามอันดับต่ำกว่า epoch 30 วิ) และ **ไม่มีทางเลื่อนย้อนกลับเข้า epoch ที่ปิดไปแล้ว**

**4) นโยบาย reconnect**
`2 → 4 → 8 → 16 → 30 → 60 วิ (ค้างที่ 60) วนไม่จำกัดตราบใดที่ยัง started` · สองขั้นแรกสั้นเพราะสาเหตุที่พบบ่อยที่สุดคือพลิกตัวจนหลุดระยะแป๊บเดียว · หางยาวถูกจำกัดที่ 60 วิ เพื่อไม่ให้สายคาดที่แบตหมดกวนวิทยุทั้งคืน · ทริกเกอร์ 3 ทาง: `onDeviceDisconnected` · error จาก monitor · `onStateChange` (บลูทูธปิด→เปิด ไม่มี disconnect event สำหรับลิงก์ที่ไม่เคยมี ⇒ เฝ้าสถานะวิทยุแยก แล้วต่อทันทีไม่ต้องรอ backoff) · มีธง `connecting` กันต่อซ้อนสองเส้น
`stop()` = ยกเลิก monitor + ปิด subscription + ล้าง timer + `cancelConnection()` + หยุด scan

**5) S8 ลงมือจริงตรงไหนบ้าง**
- จับคู่เฉพาะที่ผู้ใช้เลือก: `connect()` ถูกเรียกด้วย id จาก `devices/prefs.ts` เท่านั้น ซึ่งเขียนได้จากการ **แตะ** ในหน้า find-devices ทางเดียว · ผลสแกนไม่เคยถูกต่ออัตโนมัติ แม้ในห้องจะมีเครื่องเดียว
- payload ไม่ผ่านสคีมา = ทิ้งทั้งใบ (`parseHeartRateMeasurement` → `null`) พร้อมบันทึก `error='BLE_PAYLOAD_REJECTED'` (เงียบ ≠ พูดแล้วเราไม่เชื่อ — คนละอาการบนจอ diagnostics)
- HR 25–220: อยู่ในตัว parser + `normalizeEpochs` + `SensorEpochSchema` (เส้น epoch เดินผ่านด่านชุดเดียวกับ `WatchSensorSource`/`replay.ts`)
- dedupe/ย้อนเวลา: `(sourceId, t)` ใน engine hub · `closedUpTo` กัน sample เก่ากว่ารอบที่ปิดไปแล้ว · hub แอปกันปิดช่องเดิมซ้ำ (`lastClosedEnd`) และกันปล่อย epoch ที่ `t` ไม่เดินหน้า
- storage ก็เป็น input ที่ไม่เชื่อ: `prefs.ts` ตรวจทุกฟิลด์ตอน parse ไม่ spread ทื่อ ๆ
- แบต 0x2A19 ต้องเป็น 1 ไบต์ 0..100 ไม่งั้นไม่เชื่อ

**6) ทำไมยัง import ble-plx ได้เฉพาะ `platform/ios/`**
ไลบรารีข้ามแพลตฟอร์มก็จริง แต่ Phase 1 ไม่มีบิลด์ Android และ **บันเดิลเว็บที่ใช้ถ่าย QC ไม่มีวิทยุ** — เอาเข้ามาเมื่อไหร่ `expo export --platform web` พังทันที จึงเพิ่มชื่อมันในกติกา C ของ `fitness.mts` + `extra.iosOnlyModules` (ตรวจแล้วว่า bundle เว็บที่ export ออกมาไม่มีคำว่า `BleManager` เลย)

**7) ทำไม background mode ถึงจำเป็น และมันพอจริงไหม**
`bluetooth-central` ทำให้ CoreBluetooth ส่ง notification ต่อขณะแอปถูก suspend — ถ้าไม่มี คืนจะตาบอดตั้งแต่จอดับ · ส่วน **timer 30 วิของ hub เอง** อยู่ได้เพราะคืนนี้เปิด audio session เล่น bed ทั้งคืน (`UIBackgroundModes: audio`) ซึ่งเป็นสิ่งที่ทำให้ JS runtime ไม่ถูกแช่แข็ง — เขียนไว้ตรง ๆ ใน `epochGrid.ts` แล้วว่าเราพึ่งอะไรอยู่ (ถ้าวันหนึ่งมีโหมด "คืนเงียบไม่มี ambience" ต้องคิดใหม่ทั้งชุด — หนี้ D-4)

`scripts/visual.sh` ให้ภาษาอังกฤษเสมอ (chromium ไม่ยอมเปลี่ยน `Intl` — ปัญหาเดิมของ L1.2/L1.3) จึงใช้สคริปต์ puppeteer ชั่วคราว `/tmp/l23-th-shots.js` (ไม่ commit — เหมือน L1.2/L1.3) ซึ่ง **หว่านคีย์ `lucid.locale` ลง localStorage ก่อนสคริปต์หน้าแรกจะรัน** (`evaluateOnNewDocument`) แล้วโหลดหน้าเดียวจบ + ใช้โปรไฟล์ chromium ใหม่ต่อภาพแล้วลบทิ้งทุกใบ (กติกาดิสก์)
⚠️ ระหว่างทางเจอ **บั๊กเก่าของ fixture (ไม่ใช่ของใบนี้)**: `/plan/devices?fixture=...` บนสตอเรจว่าง ๆ จะเด้งกลับ `/plan` เพราะ `applyPlanFixture()` ลงหลัง hydration ของ `store/night.ts` บอกจอไปแล้วว่า "ไม่มีแผน" — แก้ที่การถ่ายภาพด้วยการแวะ `/plan?fixture=ble` ก่อน (เหมือนผู้ใช้จริงเดิน) ไม่ได้ไปแก้โค้ดของ L1.7ui (ดูหนี้ D-5)

## 5. สิ่งที่ R1/R2 ต้องทดสอบกับสายคาดจริง (เจ้าของอาจซื้อทีหลัง)

ทั้งไฟล์ BLE ยังไม่เคยเจอวิทยุจริงสักครั้ง — VPS ไม่มีบลูทูธ และ simulator ของ iOS ไม่มี CoreBluetooth เช่นกัน สิ่งที่ทดสอบบนเครื่องจริงเท่านั้น:
1. **เห็นในรายการไหม** — เปิดสายคาด (Polar H10 / Garmin HRM / Verity Sense) แล้วดูว่าขึ้นในหน้า `ค้นหาอุปกรณ์` ภายในไม่กี่วินาที + ชื่อที่โฆษณามาอ่านออกไหม (ถ้าไม่มีชื่อ จะขึ้น "อุปกรณ์วัดชีพจร")
2. **สิทธิ์** — ข้อความ `NSBluetoothAlwaysUsageDescription` ขึ้นตอนไหน (ต้องขึ้นตอนเข้าหน้าค้นหา ไม่ใช่ตอนเปิดแอป — เราสร้าง `BleManager` แบบ lazy ไว้เพื่อการนี้)
3. **ตัวเลขถูกไหม** — เทียบ bpm บนหน้าอุปกรณ์กับจอของสายคาด/Apple Watch พร้อมกัน 1 นาที
4. **RR/HRV มาจริงไหม** — สายคาดบางรุ่นต้องเปิดโหมดถึงจะส่ง RR · ดูใน diagnostics ว่า `hrSd` ของ epoch มาจาก RR (ค่าจะละเอียดกว่าตอนไม่มี RR ชัดเจน)
5. **ทั้งคืน + จอล็อก** — ข้อสำคัญที่สุด: เปิดคืนจริง ล็อกจอ แล้วเช้ามาดูว่า `SensorEpoch` ในฐานข้อมูลมีต่อเนื่องทั้งคืนหรือขาดหลังจอดับ (ถ้าขาด = `bluetooth-central` ไม่ได้ผลอย่างที่คิด หรือ JS timer ถูกแช่แข็ง → ต้องย้ายการปิด epoch ไปฝั่ง native)
6. **หลุดแล้วต่อกลับ** — เดินออกนอกระยะ 1 นาที กลับมา ต้องต่อเองภายใน ≤ 60 วิ และ **epoch ต้องไม่ซ้ำ/ไม่ย้อน** (ดูว่า `t` เดินหน้าอย่างเดียว)
7. **แบต** — ค่าที่โชว์ตรงกับแอปของผู้ผลิตไหม (บางรุ่นไม่มี 0x180F เลย → ต้องไม่โชว์ 0%)
8. **สองแหล่งพร้อมกัน** — ใส่ทั้งนาฬิกาและสายคาด ดูว่า `hrMean` ต่อ epoch สมเหตุสมผล (จะเอนไปทางสายคาด — ตั้งใจ ดู §2 ข้อ 2) และ `motion` เป็นค่าสูงสุด ไม่ใช่ค่าเฉลี่ยที่กลบการขยับ
9. **มือถือบนที่นอน** — วางบนที่นอนจริงแล้วดูว่า `motion` ตอนนอนนิ่งอยู่ราว 0.00–0.01 g และตอนพลิกตัวขึ้นถึงหลักสิบเท่า (ถ้าไม่ใช่ ต้องปรับเกณฑ์ `WAKE_MOTION_HIGH` ให้แยกต่อแหล่ง — ดูหนี้ D-2)

## 7. ข้อขัดแย้ง / สิ่งที่ตีความเอง (แจ้ง Fable)

1. **WO บอกว่า "ให้ hub รายงาน `sources()` เข้า `DeviceRegistry`"** — ผมทำ `sources()` ให้คืนรายงาน (ชื่อ/หมวด/ต่อแล้ว/แบต/lastDataAt/ชีพจร) จริง แต่ **การเขียนลง registry** ให้ไป delegate ที่ `devices/registry.ts` ตัวเดียว เพราะจอ `plan/devices.tsx` ก็เขียน registry เองอยู่แล้วทุก 3 วินาที ถ้า hub เขียนด้วยอีกทางจะมีแมป 2 ชุดที่เพี้ยนกันได้ (จอกลางคืนกับจออุปกรณ์เถียงกันเรื่องสายคาดเส้นเดียวกัน)
2. **ชีต "ค้นหาอุปกรณ์อื่น" ของหมวด 🎧** — WO บอกว่าหน้าใหม่ "replaces the placeholder sheet" ผมแทนเฉพาะหมวด 💓 เพราะหูฟัง/ลำโพงเป็น **Bluetooth คลาสสิก (A2DP)** ซึ่ง `react-native-ble-plx` มองไม่เห็น และ iOS ไม่อนุญาตให้แอปจับคู่แทนผู้ใช้ — การทำหน้าสแกนให้หมวดเสียงจึงเป็นการสัญญาสิ่งที่ทำไม่ได้ ผมเลยเก็บชีตไว้แต่เปลี่ยนจากชิป "เร็ว ๆ นี้" (ซึ่งไม่มีวันมา) เป็นประโยคที่พาไปตั้งค่าของ iPhone ถ้า Fable อยากให้ถอดชีตทิ้งทั้งอันก็บอกได้
3. **เพิ่ม 2 ฟิลด์ใน `SensorStatus` (`lastBpm`, `lastDataT`)** — WO สั่ง "keep the interfaces" ผมตีความว่าห้ามรื้อสัญญา `SensorSource` (ไม่ได้แตะเลย) แต่ `SensorStatus` ต้องตอบสองคำถามที่ deliverable ขอเอง: "ให้จออุปกรณ์โชว์ชีพจรสด" และ "รายงาน lastDataAt" — สายคาดที่ส่ง sample ล้วนจะมี `lastEpochT = null` ตลอดคืน ถ้าไม่มี `lastDataT` จอจะอ่านว่าอุปกรณ์เงียบทั้งที่ข้อมูลไหลอยู่ (และ `evaluateReadiness` จะตีเป็น `HEART_STALE`)
4. **`?fixture=ble` ใช้ชื่อรุ่นจริง "Polar H10 A1B2C3" / "Garmin HRM-Pro"** ตาม WO — ขอย้ำว่าเป็นของปลอมสำหรับภาพ QC เท่านั้น เจ้าของยังไม่ได้ซื้ออุปกรณ์ใด ๆ (DESIGN §8.1 หมายเหตุ 24 ก.ย.) ไม่มีที่ไหนในแอปที่อ้างว่ารองรับยี่ห้อใดเป็นพิเศษ
5. **ปักหมุด `react-native-ble-plx` เป๊ะที่ 3.5.1** (ไม่ใช่ `^3.5.1` ตามสไตล์ dep อื่น) — native module ที่ขยับเองแปลว่า pod เปลี่ยนกลางทางโดยไม่มีใครสั่ง ถ้า Fable อยากให้เข้าแถวกับ dep อื่นก็เปลี่ยนเป็น `^` ได้ในบรรทัดเดียว
