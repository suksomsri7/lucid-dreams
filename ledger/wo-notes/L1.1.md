## 3. สิ่งที่ตรวจบน Linux ไม่ได้ และต้องเทสอะไรใน R1

### 3.1 Swift ทั้งหมด — ยังไม่เคยผ่าน compiler
ไม่มี macOS/Xcode/swiftc บน VPS นี้ · โค้ดเขียนตาม API จริงแต่ **ยังไม่เคย build** (รายละเอียดใน `targets/watch/README.md`)

**ที่ prebuild บน Linux ยืนยันได้แล้ว** (`.heavy/prebuild.log` exit 0)
```
productName = LucidDream · productName = LucidWatch          ← target นาฬิกาเข้า Xcode จริง
WATCHOS_DEPLOYMENT_TARGET = 11.0
PRODUCT_BUNDLE_IDENTIFIER = app.luciddream.ios.watch
CODE_SIGN_ENTITLEMENTS = .targets/LucidWatch/generated.entitlements
generated.entitlements = healthkit + healthkit.access + healthkit.background-delivery
apps/mobile/ios/LucidDream/Info.plist → UIBackgroundModES: [audio]
```
⇒ `root: '../../targets'` ใช้ได้ (glob ของปลั๊กอินรับ `..` ได้) · plugin ทั้ง 3 ตัวรันผ่าน · ลบ `apps/mobile/ios/` ทิ้งแล้ว (อยู่ใน .gitignore)

**ต้องเทสบน Mac / EAS build รอบ R1 เรียงตามความเสี่ยง**
1. **คอมไพล์ Swift** — จุดเสี่ยงที่สุดคือ `@MainActor` บน `WorkoutManager` ปะทะ `HKLiveWorkoutBuilderDelegate`/`HKWorkoutSessionDelegate` (delegate ไม่ได้ isolate) อาจต้องใส่ `nonisolated` ที่เมธอด delegate
2. `WKCompanionAppBundleIdentifier` ใน `targets/watch/Info.plist` ฮาร์ดโค้ด `app.luciddream.ios` — ต้องตรงกับ bundle id จริงตอนมีบัญชี Apple
3. entitlement `healthkit.background-delivery` **ต้องมีใน provisioning profile ไม่งั้นบิลด์ตกเงียบ ๆ** (บทเรียน `reference_watch_target_entitlements`)
4. `ios.appleTeamId` ยังว่าง (prebuild เตือนแล้ว) → ตั้ง env `EXPO_APPLE_TEAM_ID` ตอนมีบัญชี

### 3.2 สะพาน WCSession ฝั่งมือถือ — ยังไม่มี native module
`apps/mobile/src/platform/ios/watchBridge.ts` เขียนฝั่ง JS ครบ (activate · getStatus · sendCommand · onEpoch · onStatus) แต่ native module `LucidWatchLink` **ยังไม่มี** → `requireOptionalNativeModule` คืน `null` → ทุกอย่างรายงาน "ไม่เชื่อมต่อ" แทนที่จะพัง
⇒ **R1 อ่านตัวเลข epoch/แบต จากจอนาฬิกาเอง** (`ContentView` โชว์ `Epochs n` + HR) แล้วต่อสะพานจริงที่ L2.2 (~120 บรรทัด Swift ทำ `WCSessionDelegate` + re-emit เป็น expo event — สัญญาฝั่ง JS ไม่ต้องแก้)

### 3.3 กระจกของจริง
`isLiquidGlassAvailable()` คืน `false` บนทุกอย่างที่ไม่ใช่ iOS (ตัวแพ็กเกจเองเป็นแบบนั้น) → บนเว็บเห็นแต่ fallback `expo-blur`

## 4. ข้อแย้งกับข้อสอบ (ไม่ได้แก้ไฟล์ข้อสอบ ตามคำสั่ง)

### 🔴 D-0 (บั๊กข้อสอบ) — `chk` ทำให้ข้อที่ต่อค่าหลายตัวผ่านไม่ได้เลย 7 ข้อ

`scripts/qc-L1.1.sh` บรรทัด 6–8
```bash
chk(){ local id="$1" ok="$2" msg="$3"; if [ "$ok" = 1 ]; then pass=... ; else fail=... ; fi; }
has(){  [ -e "$1" ] && echo 1 || echo 0; }   # คืน 1 ตัวอักษรเสมอ
grepq(){ grep -qs -- "$2" "$1" && echo 1 || echo 0; }   # คืน 1 ตัวอักษรเสมอ
```
`has`/`grepq` คืนอักขระเดียวเสมอ ⇒ `"$(has A)$(has B)"` ยาว 2 ตัวเสมอ ("00"/"01"/"10"/"11") ⇒ เทียบกับ `= 1` **เป็นจริงไม่ได้ทางคณิตศาสตร์** ไม่ว่าโค้ดจะถูกแค่ไหน

ค่าที่ข้อสอบคำนวณได้จาก worktree นี้ (รัน `has`/`grepq` ตัวเดียวกันมือ ๆ)

| ข้อ | ค่าที่ได้ | ต้องเป็น | เจตนาของข้อ | ตรวจมือแล้ว |
|---|---|---|---|---|
| S1.6 | `01` | `1` | มี `app.json` **หรือ** `app.config.ts` | ✅ `apps/mobile/app.config.ts` มีอยู่ |
| S1.8 | `11` | `1` | มี tsconfig **และ** `"strict": true` | ✅ ทั้งสองอย่าง |

| S4.2 | `11` | `1` | `expo-glass-effect` อยู่ทั้งใน config และ package.json | ✅ ทั้งสองที่ |

**วิธีแก้ที่เสนอ (Fable ตัดสิน — ผมไม่แตะไฟล์)**
1. แก้ `chk` ให้รับค่าที่เป็น 1 ทั้งสตริง — คืนชีพ 6 ข้อที่เป็น AND ทันที
   ```bash
   chk(){ local id="$1" ok="$2" msg="$3"
          if [ -n "$ok" ] && [ -z "${ok//1/}" ]; then pass=$((pass+1)); echo "  ✅ $id $msg"
          else fail=$((fail+1)); echo "  ❌ $id $msg"; notes+=("$id"); fi; }
   ```
2. **S1.6 ต้องแก้เพิ่ม** เพราะเจตนาเป็น OR (เห็นได้จากบรรทัดปรับแต้มของมันเองที่ลงโทษเฉพาะกรณี `= 00`) — เช่น
   `chk S1.6 "$(( $(has apps/mobile/app.json) + $(has apps/mobile/app.config.ts) > 0 ? 1 : 0 ))" ...`
3. บรรทัด "ปรับแต้มเพิ่ม" ต่อท้าย (`&& { fail=$((fail+1)); pass=$((pass-1)); }`) จะกลายเป็นการนับโทษซ้ำซ้อนเมื่อแก้ `chk` แล้ว — น่าจะเอาออกได้ทั้งหมด

## 5. บั๊กที่จับได้เองระหว่างทำ (แก้แล้ว)

**🔴 `.gitignore` บรรทัด `ios/` เปล่า ๆ กลืน `src/platform/ios/` ทั้งโฟลเดอร์**
git ตีความ pattern ที่ไม่มี `/` นำว่า "ตรงกับชื่อนี้ที่ระดับไหนก็ได้" ⇒ implementation ฝั่ง iOS ทั้ง 5 ไฟล์ + สตับ Android **หลุดจาก git เงียบ ๆ** (fitness/oracle จับไม่ได้เพราะทั้งคู่เดินไฟล์ระบบ ไม่ได้ถาม git)

แก้: ทุกบรรทัดใน `apps/mobile/.gitignore` ขึ้นต้นด้วย `/` (`/ios/` `/android/` `/dist/` `/.expo/` `/.tsbuild/`) + แก้ `ios/build/` `android/build/` ที่รากด้วย
ตรวจหลังแก้: `git check-ignore` ไม่จับไฟล์ platform แล้ว · `git add -n` เห็นครบ 6 ไฟล์ · และ `apps/mobile/ios/` (ของ prebuild) ยังถูก ignore อยู่
