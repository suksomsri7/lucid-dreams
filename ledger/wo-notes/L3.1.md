## 2. สัญญา route `/ai/score` (ให้ L3.2 อ่าน)

Request (`ScoreRequest`, `src/api/client.ts`):
```ts
{ transcript: string,
  theme: { emoji, titleTh, titleEn, place },
  seedLines: [string, string],
  answers: { dreamed, themeMatchUser, lucid, sleepQuality, cueWoke },  // ตัวไหน null ได้หมด
  lang: 'th' | 'en' }
```
Response ที่คาด: JSON ที่ตรง `AiScoreSchema` (`packages/engine/src/aiScore.ts`, มีอยู่แล้ว) — `themeMatch`/`matchedTerms`/`lucidSignals`/`tags`/`summary`/`model?` ฝั่งไคลเอนต์ไม่เชื่ออะไรจาก response เลยนอกจาก field ที่ผ่าน `sanitizeAiScore` แล้ว (คำที่ไม่อยู่ใน transcript จริงถูกทิ้ง)

วันนี้ route ยังไม่มี → ทุกคำขอได้ 404 → `postScore()` คืน `null` → `useMorning.ts` ใช้คะแนนผู้ใช้อย่างเดียวผ่าน `morningResultMessage({score:null,...})` — พฤติกรรมถูกตามที่ออกแบบไว้ ไม่ใช่บั๊ก

## 5. ข้อแย้ง (disagreements) กับ mockup

### N-1 — เฟรม b มีคำถามที่ 5 (`cueWoke`) ที่ mockup ไม่วาดไว้
`ledger/design-app/06-morning.body.html` เฟรม b มีแค่ 4 คำถาม (ฝันไหม/ตรงธีม/รู้ตัว/หลับดี) ไม่มี "เสียงเมื่อคืนปลุกคุณไหม" เลย — แต่ **ตัวคำสั่งใบงานเอง** พูดถึงคำถามนี้ตรง ๆ 2 จุด: deliverable #1 ("4 + cueWoke when cues > 0") และคำอธิบายเฟรม b ("then 'เสียงเมื่อคืนปลุกคุณไหม' only on cue nights") — ผมยึดตัวคำสั่งเป็นหลัก (ใหม่กว่า/ชัดเจนกว่าภาพ) ใส่คำถามนี้จริงในโค้ด **และ** ใน fixture `morning-result` (cuesPlayed=3 ให้ตรงกับบรรทัดผลที่พูดถึง "กระซิบ 3 ครั้ง") ทำให้ parity เฟรม b มีบล็อกเพิ่มจากภาพต้นฉบับ 1 บล็อก — วัดแล้วยังพอดีจอ ไม่ล้น จึงไม่กระทบอะไรอื่น
