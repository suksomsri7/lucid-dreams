**ทางเลือกที่พิจารณาแล้วไม่ทำ**: เปลี่ยนชื่อจอ/คีย์ `diagnostics.*` ทั้งหมดเป็นคำอื่นเพื่อเลี่ยงคำว่า diagnos — ปัดตกเพราะ (1) นอกขอบเขตใบนี้ชัดเจน แตะของ L1.1 ที่ผ่านรอบรีวิวไปแล้ว (2) เสี่ยงชนกับ builder อื่นที่อาจอ้างชื่อ route/คีย์นี้อยู่ (3) แก้ข้อสอบเองไม่ได้ตามกติกา — **แจ้ง Fable ให้ตัดสินว่าจะแก้ regex ของ O4.1 (เช่นใส่ negative lookahead กัน "diagnostics" หรือใช้ word-boundary) หรือยอมรับว่า O4.1 เป็น false-positive ที่รู้สาเหตุแล้วในใบนี้**

**ข้อความเรื่องการแพทย์ที่ใบนี้เขียนจริง** (3 ข้อในจอต้อนรับ) หลีกเลี่ยงคำต้องห้ามได้เองอยู่แล้วโดยไม่ต้องพึ่งช่องโหว่ของ oracle — ข้อความต้นฉบับจาก mockup "เป็นการฝึกความฝัน ไม่ใช่การรักษา" มีคำว่า "รักษา" ซึ่งแม้จะเขียนถูกบริบท (ปฏิเสธ) ก็ยังโดน `-o` ตัดจนติด bad เหมือนกัน (ทดสอบแยกแล้วเจอ bad=1 จากบรรทัดนี้บรรทัดเดียว) — **จึงเปลี่ยนคำจากต้นฉบับมาใช้ "ไม่ใช่การดูแลทางการแพทย์" แทน "ไม่ใช่การรักษา"** (ความหมายเดียวกัน แค่คำละคำ) ทั้ง TH="เป็นการฝึกความฝัน ไม่ใช่การดูแลทางการแพทย์" และ EN="This is dream training, not medical care." — เป็นจุดต่างจาก mockup ตัวอักษรจริง 1 คำ บันทึกไว้ในตารางพาริตี §4 ว่า "แก้แล้ว+เหตุผล" ไม่ใช่ "ยังไม่ตัดสิน"

### N-3 — เปลี่ยนชื่อ `HealthImport.requestReadAccess` → `requestAuthorization`
WO สั่งตรง ๆ ให้เพิ่มเมธอดชื่อนี้ — เดิมมี `requestReadAccess()` ทำหน้าที่เดียวกันอยู่แล้ว (เพิ่งสร้างใน L1.1 spike ยังไม่มีใครเรียกใช้จริงเลย — เช็กด้วย `grep -rn "requestReadAccess"` ก่อนแก้ พบแค่ 3 จุดประกาศ/implement ไม่มีจุดเรียกใช้) แทนที่จะมี 2 เมธอดซ้ำซ้อน (`requestReadAccess` เดิม + `requestAuthorization` ใหม่ทำงานเหมือนกัน) เลือก **เปลี่ยนชื่อเดิมทั้งระบบ** ให้เหลือชื่อเดียว ตรงกับ `SpeechToText.requestPermissions()` / `NotificationsPermission.requestAuthorization()` ใหม่ที่ตั้งชื่อคู่กัน — ปลอดภัยเพราะไม่มี call site เดิมพังจากการเปลี่ยนชื่อ

### N-4 — plugin `withInfoPlistLocales` ต้องเขียนสดในไฟล์ `app.config.ts` ไม่ใช่ไฟล์แยก
ลองแยกเป็น `apps/mobile/plugins/withInfoPlistLocales.ts` ก่อน (ตามที่ WO ใบ้ไว้ "a small config plugin") แต่รัน `expo prebuild` แล้วล้มด้วย `Cannot find module './plugins/withInfoPlistLocales'` — `expo/config`'s loader ทรานส์ไพล์เฉพาะไฟล์ `app.config.ts` เองแบบ on-the-fly แต่ไม่ได้ส่ง require ของไฟล์ TS ที่ import แบบ relative ผ่าน loader เดียวกันต่อ (ไฟล์ `.ts` ธรรมดาเรียกด้วย `require()` ตรง ๆ ไม่ผ่าน transpile) — ย้ายโค้ดทั้งหมดเข้าไปอยู่ใน `app.config.ts` ไฟล์เดียวแล้วรัน prebuild ซ้ำ ผ่าน (ดู §0 · หลักฐานไฟล์ `.lproj` ที่ได้จริง)

**ขอบเขตที่ตั้งใจไม่ทำ**: plugin คัดลอกไฟล์ `.strings` เข้า `ios/<project>/<lang>.lproj/` เท่านั้น **ไม่ได้ลงทะเบียนเป็น `PBXVariantGroup` ใน `.pbxproj`** (ขั้นที่ทำให้ Xcode build จริงเอาไฟล์นี้ไปรวมในแอป) — เครื่องนี้ไม่มี Mac/Xcode ให้ทดสอบการแก้ pbxproj ทำผิดมีสิทธิ์ได้ project file พังแบบเงียบ ๆ (โผล่ตอนมีคน build จริงครั้งแรก) ซึ่งแย่กว่าการทิ้งหนี้ที่รู้ตัวไว้ชัดเจน — บันทึกเป็นหนี้ §5

### N-5 — คำอธิบายใบ L1.3 ใน `APP-RUN.md` §2 บรรทัดเดียวเก่ากว่ามติ mockup

### N-6 — `scripts/visual.sh ... th` เรนเดอร์เป็นอังกฤษ (ไม่ใช่บั๊กของแอป — chromium บนเครื่องนี้ไม่รับ `--lang`)
รัน `visual.sh ... th` ตามที่สั่ง ได้ภาพเป็น**ภาษาอังกฤษ**ทั้งที่ควรเป็นไทย — ตรวจแล้วพบว่า snap chromium headless บนเครื่องนี้เพิกเฉยต่อ `--lang=th` จริง ๆ:
```
$ chromium --headless --lang=th --dump-dom "data:text/html,<script>document.write(new Intl.DateTimeFormat().resolvedOptions().locale)</script>"
→ en-US
```
แอปตรวจภาษาเริ่มต้นจาก `Intl.DateTimeFormat().resolvedOptions().locale` (ตาม `src/i18n/index.ts` ที่ L1.2 วางไว้ อ่านจาก `navigator.language`) — เมื่อ chromium ไม่ยอมเปลี่ยนค่านี้ แอปก็เดาเป็น `en` ถูกต้องตามตรรกะของมันเอง (ไม่ใช่บั๊ก แค่เครื่องมือถ่ายภาพใช้ไม่ได้กับกลไกนี้) — ตรงกับที่ L1.2's builder เจอมาก่อนแล้วและแก้ด้วยการ "คลิกจริงผ่าน DOM" แทน (`ledger/wo-notes/L1.2.md` §0) ผมทำแบบเดียวกัน: เขียนสคริปต์ `puppeteer-core` ชั่วคราว (ใช้ `/root/qc/node_modules/puppeteer-core` ที่มีอยู่แล้วในเครื่อง ไม่เพิ่ม dependency ในโปรเจกต์) คลิกปุ่ม `Seg` "ไทย" จริงที่ `/onboarding` แล้วถ่ายภาพ 2 จอ (locale ติดไปกับ `localStorage` ตอน goto หน้าอุปกรณ์ต่อ) — สคริปต์อยู่ที่ `/tmp/l13-th-shots.js` ไม่ commit เข้า repo (ไม่ใช่ deliverable เหมือนที่ L1.2 ทำ) — ภาพ TH ใน `.qc-shots/L1.3/` ที่ใช้ทำพาริตี §4 คือภาพจากสคริปต์นี้ ไม่ใช่จาก `visual.sh` ตรง ๆ
