## ทำอะไร / ทำไม

ก่อนใบนี้ เหตุการณ์ `WHISPER_SEED` ที่นาทีที่ 3 และ 8 มีแค่ `console.log` แล้วเขียนแถว `SEED` ลง DB ด้วย
`played: true` แบบฮาร์ดโค้ด — คนนอนไม่เคยได้ยินประโยคปลูกภาพเลยสักคืน (หนี้ที่หัวไฟล์ `src/audio/anchor.ts`
แบกมาตั้งแต่ L1.7ui) ใบนี้จ่ายหนี้ก้อนนั้น และจัดระดับเสียงทั้งคืนให้เป็นไปตามตารางปล่อยเสียงในใบงาน

1. **`apps/mobile/src/api/client.ts` — `fetchTtsAudio({text, lang})`**
   ยิง `POST /ai/tts` ด้วย device token (`voice: 'whisper'` ฮาร์ดโค้ด เพราะแอปไม่มีตัวเลือกเสียง) ·
   `AbortController` 15 s · ลอง token ใหม่ 1 ครั้งเมื่อ 401 · **ไม่ throw** (คืน `{ok:false, …}`)
   — นโยบายเดียวกับ `fetchAnchorAudio` เป๊ะ

2. **`apps/mobile/src/audio/seedRemote.ts` (ไฟล์ใหม่)**
   - `SEED_AUDIO_VERSION = 'george-1'`
   - `ensureSeedLineUri(text, lang, {cachedOnly?})` → ไฟล์ `Paths.cache/seed/<hash(text|lang|version)>.mp3`
     มีแล้ว → คืน uri ทันที · ไม่มี → ดาวน์โหลด · ตรวจ `audio/mpeg` + ขนาด ≥ 8 KB ก่อนเขียน ·
     เว็บ → `null` โดยไม่แตะเน็ต · ทุกทางล้ม → `null` + `console.warn` ไม่มีทางไหน throw
   - `prefetchSeedLines(plan, lang)` — in-flight promise เดียว (3 จุดเรียกห่างกันไม่กี่วินาที),
     ดึงทีละประโยค (ไม่ขนาน) เพราะเซิร์ฟเวอร์จำกัดอัตราต่อเครื่อง และ MISS 2 อันพร้อมกันไม่ได้อะไรคุ้ม
   - เรียกจาก 3 จุด: `useAdvisor.start()` (หลัง `saveTonightPlan`) · `AdvisorRoom.handleStart` ·
     `startNightSession` ก่อน `startBed`

3. **`apps/mobile/src/night/session.ts`**
   - จำ `currentBedVolume` (เริ่มที่ `BED_VOLUME_FULL` = ระดับที่ `startBed` ถูกเรียก) และอัปเดตทุก
     `SET_BED_VOLUME`; ระหว่าง duck จะ *จำอย่างเดียวไม่สั่ง* แล้วให้ `restoreBed` พาไปที่ค่าล่าสุด
     (เอนจินยิง `SET_BED_VOLUME` ทุก epoch ตอนเฟดหลังหลับ ถ้าปล่อยผ่านจะทับ duck กลางประโยค)
   - `WHISPER_SEED` → `speakSeedLine(index)`: รอ uri ไม่เกิน 3 s → duck เสียงพื้นไป `BED_DUCK_SEED`
     → หน่วง 0.5 s → `playOneShot({source, volume: SEED_VOLUME, pan: 0})` (resolve ตอนคลิปจบจริง)
     → หน่วง 1 s → คืน `currentBedVolume` · แถว `SEED` เขียนลง DB **หลัง** พยายามเล่นเสร็จ ด้วย
     `played: seedPlayed` ของจริง (`atIso` ยังเป็นเวลาของเหตุการณ์ ไม่ใช่เวลาที่เขียน)
   - `PLAY_CUE` → duck ไป `BED_DUCK_CUE` ก่อนเรียก `playAnchorOnce` แล้วคืนค่าแบบไต่ 3 ขั้น ๆ ละ 1 s
   - ธง `oneShotBusy` กันเสียงสองตัวทับกัน (seed ยอม cue เสมอ ไม่ใช่ทางกลับกัน)
   - ค่าคงที่อยู่ในไฟล์เดียวกัน: `SEED_VOLUME = 0.35` · `BED_DUCK_SEED = 0.06` · `BED_DUCK_CUE = 0.03`

4. **เสียงบรรยากาศ** ไม่ได้แตะ — ยืนยันว่าเส้นทาง loop เดิมยังอยู่ (`IosAudioPlayer.startBed` →
   `this.player.loop = true` บรรทัด 146) และไฟล์ที่ Fable วางไว้ยาว **57.000 s** ทั้ง 3 ตัว

## จุดที่ทำต่างจากใบงาน

1. **ชื่อไฟล์แคชไม่ได้ใช้ sha1** — แอปไม่มี dependency ฝั่ง crypto (`expo-crypto` ไม่ได้ติดตั้ง และใบนี้ห้าม
   เพิ่ม dependency) ส่วน `stableHash` ของ engine ไม่ได้ export และ `packages/*` ห้ามแตะ จึงทำ FNV-1a
   สองทิศ (เหมือนสูตรของ engine) ไว้ในไฟล์ — คีย์ยังเป็น `text|lang|version` ตามใบงาน และงานนี้ต้องการแค่
   ชื่อไฟล์แคชของข้อความสาธารณะ ไม่ใช่ลายเซ็นเข้ารหัส
2. **`SET_BED_VOLUME` ถูกกลืนไว้ระหว่าง duck** (จำค่าไว้ แล้วไปโผล่ตอนคืนค่า) — ใบงานไม่ได้สั่ง แต่ถ้าไม่ทำ
   เฟดหลังหลับจะดันเสียงพื้นกลับขึ้นมากลางประโยค
3. **แถว SEED บันทึก `volume: SEED_VOLUME (0.35)`** แทน `params.volumeStart` เดิม — เพราะตอนนี้เป็นระดับที่
   เล่นจริง
4. **แถว SEED เขียนช้ากว่าเหตุการณ์ ~6 s** (รอผลว่าเล่นได้จริงไหม) — `atIso` ยังตรงเวลาเหตุการณ์

## หนี้ที่ทิ้งไว้

1. **ประโยคยาวเกิน 120 ตัวอักษรจะไม่ถูกพูด** — `TtsBodySchema` ฝั่งเซิร์ฟเวอร์ตัดที่ `TTS_MAX_TEXT = 120`
   แต่ `DreamPlanSchema` ยอมให้ยาวได้ 200 ⇒ ประโยคที่ AI แต่งเองยาว ๆ จะโดนข้าม (แอปเช็คเองก่อนยิง เพื่อไม่
   เสียรอบเน็ตกับ 400) ธีมสำเร็จรูปทุกธีมยาว ≤ 80 จึงไม่กระทบคืนนี้ · ต้องเคาะว่าจะขยายเพดานเซิร์ฟเวอร์หรือ
   บังคับความยาวตอนสร้างแผน
2. **`played: false` ไม่บอกสาเหตุ** — ตาราง cue ไม่มีคอลัมน์ให้ (`packages/data` ห้ามแตะ) เหตุผลอยู่ใน
   `console.warn` อย่างเดียว
3. **duck เป็นขั้นบันได ไม่ใช่การไล่ระดับ** — `expo-audio` ไม่มี API เฟด และ `setVolume` เปลี่ยนค่าทันที
   (ตอน seed คืนค่าขั้นเดียว · ตอน cue ไต่ 3 ขั้น) ถ้าฟังแล้วสะดุดค่อยทำเป็น timer ไล่ทีละ 50 ms
4. **เว็บ/fixture ไม่ครอบคลุมเสียง seed** — บนเว็บคืน `null` เสมอ ⇒ ข้อสอบพิสูจน์ได้แค่โครงสร้างโค้ด
   ตัวจริงต้องพิสูจน์ด้วยหูคืนนี้

## R1 — สิ่งที่เจ้าของต้องเช็คคืนนี้ (ธีม "บินได้")

1. **กด "เริ่มคืนนี้"** → ได้ยินระฆัง+เสียงกระซิบ 1 รอบ แล้ว **เสียงลมเริ่มดังต่อเนื่อง** (0.2 บนหูฟัง)
   — ถ้าเงียบสนิทแปลว่าเสียงพื้นไม่ติด ไม่ใช่เรื่องของใบนี้
2. **นาทีที่ 3** → ได้ยินประโยค "The ground lets go of your feet…" (หรือฉบับไทย) และ **เสียงลมเบาลง
   ชัดเจนตอนพูด** แล้วกลับมาเท่าเดิมหลังพูดจบ ~1 วินาที
3. **นาทีที่ 8** → ประโยคที่ 2 แบบเดียวกัน (ถ้าหลับไปก่อนแล้ว เอนจินจะข้าม — ไม่ใช่บั๊ก)
4. **หลังหลับ** → เสียงลมค่อย ๆ เบาลงจาก 0.2 เหลือ 0.08 ภายใน 1 นาที
5. **ตอนเช้า** → หน้ารายงานต้องมีแถว "ปลูกภาพ" (SEED) **2 แถว และ `played = true` ทั้งคู่**
   ถ้าเป็น false แปลว่าคลิปโหลดไม่ทัน/ไม่มีเน็ตตอนกดเริ่ม — ดู log `[seed]` ใน diagnostics
6. ถ้ามี REM cue กลางคืน: เสียงลมต้องเบาลงเหลือแทบไม่ได้ยินตอนระฆังดัง แล้วไต่กลับใน 3 วินาที
