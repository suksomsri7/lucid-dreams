## 3. ข้อแย้ง/หมายเหตุกับสัญญา WO (ไม่ได้แก้ข้อสอบ)

### N-1 — `FloatingTabBar` ไม่รับ React Navigation `tabBar` props ตรง ๆ
สัญญาบอก "แถบแท็บลอย" อย่างเดียว ไม่ได้กำหนด signature — ผมออกแบบให้ `FloatingTabBar` รับ `{items, activeKey, onPress}` แบบกลาง (ไม่รู้จัก React Navigation เลย) แล้วให้ `app/(tabs)/_layout.tsx` เป็นตัวแปลง `tabBar` render-prop (state/navigation) → ให้ props แบบกลางนี้ เหตุผล: คอมโพเนนต์เดียวกันใช้ได้ทั้งในแท็บจริง **และ** ใน `/dev/ui` gallery (ที่ผูกกับ `useState` ธรรมดา ไม่มี navigation object) โดยไม่ต้อง mock React Navigation — ตรงกับที่สัญญาขอ "หน้า `/dev/ui` แสดงทุกคอมโพเนนต์" ได้ง่ายกว่า

### N-2 — `Band` รับสัดส่วน (fraction 0–1) ไม่ใช่เวลานาฬิกา
สัญญาไม่ได้ระบุหน่วย ผมเลือก fraction เพราะ `Band` เป็นคอมโพเนนต์ล้วน (pure) ไม่ควรรู้จักโซนเวลา/`now()` (ตรง §0.2 ข้อ 6 "ข้อสอบห้ามพึ่งเวลาจริง" — ยกมาเป็นหลักการออกแบบคอมโพเนนต์ด้วย) ตัวแปลง `Date` จริงของคืนนั้น → สัดส่วน เป็นงานของ L2.10/L3.5 ที่จะมีข้อมูล `SensorEpoch`/`CueEvent` จริงให้แปลง

### N-3 — เพิ่ม `background`/`contentStyle` ให้ `GlassSurface` (ไม่มีในสัญญา) — จำเป็นเพื่อแก้บั๊กจริง ดู §5

## 5. บั๊กที่จับได้เอง (สำคัญ — อ่านก่อนต่อยอดคอมโพเนนต์กระจกในใบถัดไป)

### 🔴 B-1 — เลย์เอาต์หลายลูกพังเงียบ ๆ: ชั้นห่อของ platform แทรก View เกินมา 1 ชั้น
**อาการที่เห็น**: ธีมชิปในหน้า "คืนนี้" เรียงเป็นคอลัมน์แนวตั้งแทนที่จะ wrap เป็นแถว, `FloatingTabBar` เรียง 3 แท็บซ้อนกันแนวตั้งแทนแถวนอน, `Composer` (ช่องพิมพ์+ไมค์+ส่ง) ก็ซ้อนแนวตั้งเหมือนกัน

**ต้นเหตุ**: `src/platform/shared/BlurSurface.tsx` (และคู่ `ios/GlassSurface.tsx`) ห่อ `children` ไว้ใน `<View style={styles.content}>{children}</View>` เสมอ (`content:{flexShrink:1}`) — ค่า `style` ที่ `ui/GlassSurface` ส่งเข้าไป (เช่น `flexDirection:'row', gap:8`) ไปลงที่ **`BlurView` ตัวนอก** ซึ่งมีลูกแค่ตัวเดียว (คือ `content` view) ทำให้ row/gap ไม่มีผลอะไรเลย ตัวที่กำหนดว่าลูกจริงเรียงยังไงคือ `content` view ที่ default เป็น `column` เสมอ

**วิธีตรวจเจอ**: ข้อสอบ oracle (typecheck/fitness/export) ผ่านหมดโดยไม่รู้เรื่องนี้เลย — export สำเร็จไม่ได้แปลว่าเลย์เอาต์ถูก จับได้จาก **เรนเดอร์จริงด้วย puppeteer แล้วถ่ายภาพดู** เทียบ mockup (บทเรียนเดียวกับ `feedback_visual_qc_before_deliver`)

**วิธีแก้**: คอมโพเนนต์ที่มีลูกหลายตัวต้องเรียงกัน (Composer, FloatingTabBar) ห่อลูกด้วย `<View>` ของตัวเองอีกชั้นก่อนส่งเข้า `GlassSurface` (มี comment อธิบายเหตุผลไว้ในโค้ดทั้งสองไฟล์) — **ไม่ได้แก้ที่ `src/platform/*` โดยตรง** (ลอง `flex:1` ที่ `content` แล้วแต่จะพังกรณี auto-height ที่ไม่มี `height` กำหนด — ตรงกับบทเรียน `reference_rn_flex1_in_auto_height_sheet` ที่มีอยู่แล้วในความจำ) เลือกแก้จุดเรียกใช้แทนเพื่อไม่กระทบพฤติกรรมของ L1.1 ที่ยืนยันบนเครื่องจริงแล้ว (Diagnostics ใช้ชั้นนี้เหมือนกัน)

### 🔴 B-2 — สีพื้นทึบ (Button.pri/acc/dg, Chip.on/acc/rem/dg, Bubble.me, GlassCard.acc) จางหายบนเว็บ
**อาการที่เห็น**: ปุ่ม "เริ่มคืนนี้" (ควรดำทึบ+ตัวขาว) ขึ้นเป็นสีขาวซีดจางแทบมองไม่เห็นตัวหนังสือ บับเบิลข้อความผู้ใช้ (ควรม่วงทึบ) ก็จางเหมือนกัน

**ต้นเหตุ**: `expo-blur`'s เวอร์ชันเว็บ (`node_modules/expo-blur/src/BlurView.web.tsx`) คำนวณสีพื้นหลังของตัวเองจาก `tint`/`intensity` แล้ว **ปะทับท้าย** อาร์เรย์ style ของตัวเอง (`style={[style, blurStyle]}`) — `backgroundColor` ที่ผมส่งผ่าน `style` เข้าไปเลยโดนสีของ `blurStyle` ทับทุกครั้ง ไม่ว่าจะสั่งสีอะไร (นี่คือโค้ดของแพ็กเกจเอง ไม่ใช่บั๊กที่ผมแก้ได้ตรง ๆ)

**วิธีแก้**: เปลี่ยนสถาปัตยกรรม `GlassSurface`: สีพื้นหลังไม่ผ่าน `style.backgroundColor` ของตัว `BlurView`/`GlassView` อีกต่อไป แต่วาดเป็น **View ลูกทึบแสง** (`background` prop ใหม่) ซ้อนอยู่ *ข้างใน* — เพราะลูกวาดทับพื้นหลังของพ่อเสมอไม่ว่าพ่อจะเลือกสีอะไรมาก่อน ผลคือสีที่ถูกต้องแสดงออกมาจริงไม่ว่า `expo-blur` จะพยายามทับแค่ไหน (กระทบเฉพาะ fallback เว็บ/บล็อกความละเอียดต่ำ — ของจริงบน iOS 26 ใช้ `expo-glass-effect` ที่ไม่มีบั๊กนี้ แต่ QC ทั้งหมดถ่ายจากเว็บ ตาม APP-RUN §0.2 ข้อ 2 จึงต้องแก้ที่นี่)

**ผลข้างเคียงที่ต้องแก้ตาม**: เมื่อ background ย้ายไปเป็น View ลูก การอ้าง `height`/`padding` ที่เคยฝากไว้กับ `style` (ตัวนอก) ก็ไม่ถึงกล่องที่มองเห็นจริงอีกต่อไป (ตัวนอกไม่ยืดตาม `height` ที่ตั้งเพราะลูกที่แท้จริงคือ `content` wrapper ของ platform ที่ auto-size) → เพิ่ม prop ที่สอง **`contentStyle`** แยกออกจาก `style`: `style` = การวางตัวเอง+ทรง (flexGrow/flexBasis/มุมตัด — สิ่งที่ต้องกระทบ "กรอบนอกจริง" เพื่อ clip ถูกทรง) ส่วน `contentStyle` = ขนาด/padding/การเรียงลูกของเนื้อหาจริง คอมโพเนนต์ที่แก้ตาม: `Button.tsx` `Bubble.tsx` `GlassCard.tsx` (ไล่รายละเอียดเต็มใน commit diff — ทุกจุดมี comment อธิบาย)

**ยืนยันแล้ว**: ถ่ายภาพซ้ำหลังแก้ — ปุ่ม/ชิป/บับเบิลสีทึบทุกโทนแสดงถูกต้องครบทั้งโหมดสว่าง/กลางคืน (ดู `.qc-shots` ที่ Fable จะถ่ายซ้ำในขั้นตอนถัดไป — ผมเก็บภาพชั่วคราวไว้ที่ `/tmp/shot-*.png` บนเครื่องนี้ ไม่ได้ commit เข้า repo เพราะไม่ใช่ deliverable)

### 🔴 B-3 (Fable จับได้จากภาพจริง หลัง review รอบแรก) — `Seg` (ไทย/English) ที่ `/settings` แถบเบียดทับตัวหนังสือ
**อาการที่เห็น**: แถว "Language" ที่ `/settings` — `Seg` บีบแคบเหลือ ~110px, ตัวหนังสือ "English" ล้นออกนอกกล่องที่เลือก (pill) ที่ `/dev/ui` ไม่เจอเพราะ `Seg` ที่นั่นอยู่ในการ์ดเต็มความกว้าง ไม่ได้ถูกบีบ

**ต้นเหตุ**: `Seg.tsx`'s `item` (แต่ละตัวเลือก) ใช้ `flex:1` ล้วน ๆ ไม่มี `minWidth` และ `track` (ตัวห่อ) ก็ไม่มีขนาดขั้นต่ำของตัวเอง — เมื่ออยู่ในแถวเดียวกับ `Row`'s `label` (ที่เป็น `flex:1` เหมือนกัน แต่ `flexBasis:0%` ทำให้มันยอมหด) Yoga คำนวณขนาดเริ่มต้นของ `track` จากเนื้อหาน้อยที่สุดเท่าที่จะเป็นไปได้ (เพราะ parent ไม่มีความกว้างที่แน่นอนให้อ้างอิงตอนแจก `flex`) → ได้กล่องแคบกว่าที่ตัวหนังสือต้องการจริง ตัวหนังสือ (ไม่มี `numberOfLines`) เลยล้นออกนอกกรอบไอเทมของตัวเอง ดูเหมือนกล่อง pill ทับตัวหนังสือ

**วิธีแก้** (`Seg.tsx` + `app/(tabs)/settings.tsx`):
1. `item` เพิ่ม `minWidth: 72` + `paddingHorizontal` — กันไม่ให้ตัวเลือกแคบกว่าที่อ่านได้ ไม่ว่าจะอยู่ในบริบทไหน
2. `track` เพิ่ม `minWidth` (คำนวณจาก 2×72 + gap + padding แทนเลขลอย ๆ) — กัน parent (`Row`) บีบเกินขนาดขั้นต่ำของลูก
3. `Text` ของแต่ละตัวเลือกเพิ่ม `numberOfLines={1}` — กันข้อความยาวกว่าที่คาดในอนาคต (ภาษาที่ 3?) ล้นแทนที่จะโดนตัด
4. `settings.tsx`: ห่อ `<Seg>` ด้วย `<View style={{minWidth:160}}>` ก่อนส่งเข้า `Row`'s `right` — กันชั้นสอง (`Seg`'s ของตัวเองพอแล้ว แต่เผื่อจุดเรียกอื่นในอนาคตที่ไม่ผ่าน `Seg`'s default)

**ตรวจเพิ่มตามที่ขอ**: ไล่ดู `right=` ทุกจุดที่เรียกใน `app/`+`src/ui/` — มีแค่ 2 จุด: `Seg` (แก้แล้ว) กับ `Switch` (ขนาดคงที่ 50×30 ไม่ใช้ `flex` เลย ไม่มีทางถูกบีบแบบนี้ได้) — ไม่มีคอมโพเนนต์อื่นอยู่ในรูปแบบเดียวกันที่เสี่ยง · แถวชิป (`Chip` + `flexWrap`) เช็กซ้ำที่หน้าจอกว้าง 390px (เท่าเฟรม iPhone จริง ไม่ใช่แค่ 900px ตอนรีวิวรอบแรก) — ห่อบรรทัดถูกต้อง ("อื่น ๆ"/"Other" ตกไปบรรทัด 2 ทั้งโหมดสว่าง/กลางคืน) · การ์ด 3 ใบ (regular/soft/acc glass) ที่ 390px ห่อเป็น 2 แถวตามที่ `flexBasis:140` ควรทำ ไม่ใช่บั๊ก · `Scale` (11 ชิป 0–10) ยังไม่ได้ใส่ `minWidth` ต่อชิปเหมือน `Seg` เพราะยังไม่มีจุดเรียกไหนวางมันในกล่องแคบ (ใช้แค่ในการ์ดเต็มความกว้างที่ `/dev/ui`) — ทิ้งเป็นหนี้ D-5 เผื่อ L1.3 เอาไปใช้ในบริบทแคบกว่านี้

**ยืนยันแล้ว**: ถ่ายภาพซ้ำที่ 390×844 (ขนาดจริงของเฟรม ไม่ใช่ 430×932 ที่ใช้ตอนรีวิวรอบแรก) — `/settings` แถบ Thai/English แสดงครบไม่ล้น pill ขยับตามตัวที่เลือกถูกต้อง · `/dev/ui` เต็มหน้าที่ 390px ไม่มีจุดพัง
