# ใบงาน L3.8 — เสียงสมอเต็ม (ระฆัง + กระซิบ George) ต้องถึงเครื่องผู้ใช้

## ทำไม (พบ 25 ก.ย. 2026 ระหว่างเจ้าของเลือกเสียง)
แอปตอนนี้เล่น **ระฆังอย่างเดียว**: `src/audio/anchor.ts` เรนเดอร์ WAV จาก engine ในเครื่อง ส่วนประโยคกระซิบอยู่บนเซิร์ฟเวอร์ (`POST /ai/anchor` คืน mp3 ระฆัง+กระซิบ 9.8 s) แต่ **ไม่มีที่ไหนในแอปเรียก** (หนี้จาก L1.7ui ที่ไม่ถูกปิด) ⇒ คืนแรกผู้ใช้จะไม่ได้ยิน "You are dreaming." เลย · เจ้าของเพิ่งเลือกเสียง George และเซิร์ฟเวอร์อุ่นแคชแล้ว (`/root/.lucid/tts/anchor-prod-George-2026-09-25.mp3` = ผลจริง)

## เซิร์ฟเวอร์ (Fable ทำแล้ว ห้ามแตะ apps/api)
- `POST /ai/anchor` body `{seed, lang:'th'|'en'}` header `authorization: Bearer <device token>` → `200 audio/mpeg` + headers `x-cache: HIT|MISS`, `x-anchor-hash: <signature.hash>`, `x-anchor-notes` · MISS ครั้งแรก ~4 s (ffmpeg) · HIT 30 ms · rate limit ต่อ device ต่อชั่วโมง (429) · ไม่พร้อม = 501/502 JSON `{error}`
- ไฟล์ยาว = ระฆัง 9.84 s · กระซิบเริ่ม 2.6 s · เสียงต่อ seed+lang (hash ของผู้ใช้) — ไฟล์ของคนอื่นใช้ไม่ได้

## งาน builder (apps/mobile เท่านั้น)
### A `src/audio/anchorRemote.ts`
- `export const FULL_ANCHOR_VERSION = 'george-1'` (อยู่ในชื่อไฟล์แคช: `<hash>-<lang>-<version>.mp3` ใน `Paths.cache/anchor/` เดียวกับ anchor.ts) — เปลี่ยนเสียงบนเซิร์ฟเวอร์ครั้งหน้า = bump แล้วเครื่องโหลดใหม่
- `export async function ensureFullAnchorUri(signature: AnchorSignature, lang: AnchorLang): Promise<string | null>` — มีไฟล์ → คืน uri ทันที · ไม่มี → เรียก `fetchAnchorAudio({seed, lang})` ใน `src/api/client.ts` (เพิ่มฟังก์ชันใหม่ข้าง `requestDreamPlan` ใช้ device token เดิม · `AbortController` timeout 15 s · ตรวจ `response.ok` + `content-type` audio/mpeg + `x-anchor-hash === signature.hash` ไม่ตรง = ทิ้ง) → เขียนไฟล์ด้วย `File.write(bytes)` (expo-file-system API ใหม่ที่ anchor.ts ใช้) → คืน uri · ทุก error → `null` + `console.warn` (ห้าม throw)
- `Platform.OS === 'web'` → คืน `null` ทันที ไม่ยิง network
- `export async function prefetchFullAnchor(): Promise<boolean>` = seed (`getAnchorSeed`) + lang ปัจจุบัน → `ensureFullAnchorUri` → true/false · กันเรียกซ้อน (in-flight promise เดียว)
- `export function clearFullAnchorCache()` ลบไฟล์ `*-<version>.mp3` · ให้ `resetAnchorSeed()` ใน anchor.ts เรียกด้วย (รีเซ็ตลายน้ำ = เสียงใหม่ทั้งชุด)
- `export async function fullAnchorStatus(): Promise<'ready'|'missing'>` สำหรับหน้าจอ

### B ใช้งาน
- `src/audio/player.ts#playAnchorOnce`: ถ้า `pan === 0` → ลอง `ensureFullAnchorUri(signature, lang)` (lang จาก i18n locale · ต้องส่งเข้ามาหรืออ่านจาก `getLocale()`) ได้ uri → `playOneShot({source: uri, volume, pan: 0})` · null → ระฆัง WAV เดิม · **pan ≠ 0 (หูซ้าย/ขวา) ไม่เปลี่ยน** ใช้ระฆังสั้น WAV
- คืนกลางคืน (`src/night/session.ts` PLAY_CUE): ผ่าน `playAnchorOnce` อยู่แล้ว → เพิ่มบันทึกลง diagnostics/audio event ว่า cue เล่น `fullAnchor: true|false` (ดูโครง audio event ที่มีใน session.ts/diagnostics) เพื่อ R1 รู้ว่าคืนนั้นมีกระซิบจริงไหม
- prefetch 3 จุด (ไม่ await ไม่บล็อก UI): (1) ตอนเปิดแอปหลัง intro เริ่ม (ใน `IntroOverlay` หรือ `_layout`) (2) ตอนกด Start tonight (`AdvisorRoom.handleStart` ข้าง `playBrandAnchor`) (3) ตอนเข้าหน้า `app/plan/devices.tsx`
- หน้า `app/plan/devices.tsx`: เพิ่มแถวสถานะเล็กใต้รายการอุปกรณ์ (สไตล์เดียวกับแถวอื่น ไม่มีปุ่ม): `plan.anchor.ready` "เสียงกระซิบพร้อมแล้ว (ออฟไลน์ได้)" / `plan.anchor.loading` "กำลังโหลดเสียงกระซิบ…" / `plan.anchor.offline` "ยังไม่มีเสียงกระซิบ คืนนี้จะได้ยินเฉพาะเสียงระฆัง" — **ไม่บล็อกปุ่มเริ่ม** (readiness ไม่เปลี่ยน) · i18n th/en ครบ · ห้ามให้ mockup 04 เพี้ยน: แถวนี้แทรกใต้หมวดสุดท้าย ความสูงแถวเดียว
- `playBrandAnchor` (เสียงเปิดแอป/Start tonight) ผ่าน `playAnchorOnce` pan 0 → ได้เสียงเต็มอัตโนมัติเมื่อมีไฟล์ (ครั้งแรกอาจเป็นระฆังอย่างเดียว ยอมรับ)
