## 1. `signature.ts` — ลายน้ำเสียงสมอ (DESIGN §2 ข้อ 3)

### ทำไมต้อง "เอกลักษณ์" และ "เพราะ" พร้อมกัน
ลายน้ำมีเงื่อนไขขัดกันเอง 2 ข้อ: ต้อง **ไม่ซ้ำคนอื่น** (ไม่งั้นไม่ใช่ลายน้ำ) แต่ต้อง **ไพเราะพอจะฟังซ้ำทุกคืนหลายเดือน** (ไม่งั้นผู้ใช้ปิดแอป) · สุ่มโน้ตอิสระจะได้ทั้งเสียงคู่เพี้ยนและกระโดดเหมือนเสียงเตือนภัย จึงบีบพื้นที่สุ่มด้วยกฎรูปร่าง 4 ข้อ:

| กฎ | ค่า | เหตุผล |
|---|---|---|
| สเกล | เพนตาโทนิกเมเจอร์ 2 ช่วงเสียง `[0,2,4,7,9,12,14,16,19,21]` | สเกลนี้ไม่มีคู่ไมเนอร์เซคันด์และไม่มีไทรโทน ⇒ **เซตย่อยใด ๆ ก็เข้ากัน** เครื่องสุ่มจึงไม่มีทางหยิบคู่เสียงน่าเกลียด |
| รากเสียง | midi 55–63 | รากสูงสุด 63 + ขั้น 21 = 84 ⇒ ทุกโน้ตอยู่ใน 48–84 ตามข้อสอบ G3 โดยไม่ต้อง clamp (clamp จะทำลายสเกล) |
| ก้าวโน้ต | ห่างไม่เกิน 7 เซมิโทน · ห้ามซ้ำโน้ตติดกัน | เกิน 7 = กระโดดแบบไซเรน · ซ้ำติดกัน = ฟังเป็นเสียงติดขัด |
| โน้ตสุดท้าย | ต้องไม่เท่าโน้ตแรก | ทำนองที่ "กลับบ้าน" ฟังเหมือนจบแล้ว จำยากกว่าทำนองค้าง (จำง่ายคือหัวใจของการฝึก) |

โน้ต 3–4 ตัว · ความยาวรวม 1200–1800 ms (ออกแบบไว้ที่ "ลายเสียงสั้น 1.5 วิ") · ท้ายคลิปเว้น `tailMs = releaseMs + 120` ให้เสียงจบด้วยการเฟด ไม่ใช่ถูกตัด · เอนเวโลป ADSR สุ่มต่อ seed (attack 12–60 · decay 90–300 · sustain 0.25–0.6 · release 260–560) · เนื้อเสียง = ฮาร์มอนิก 2–3 ชั้น + detune 2–9 เซนต์ (สแต็กฮาร์มอนิกเป๊ะ ๆ ฟังเป็นเสียงสังเคราะห์ ไม่ใช่เครื่องดนตรี)

### deterministic
`seed` (สตริงหรือเลข) → FNV-1a 32 บิต → `mulberry32` จาก `rng.ts` · ทุกตัวเลขที่เก็บถูกปัดก่อนเข้า hash ⇒ ประกอบใหม่ได้ไบต์ต่อไบต์ทั้งบนมือถือและบน VPS (ผู้ใช้ลงแอปใหม่ต้องไม่เสียเสียงที่ฝึกมาแล้ว) · `hash` = FNV-1a ไปหน้า + FNV-1a สตริงกลับหลัง (offset ต่างกัน) = hex 16 ตัว ของ `(notes, noteMs, envelope, timbre, lang)`

### ภาษา
`th`/`en` ใช้ **โน้ตชุดเดียวกัน** (ข้อสอบ G4) เพราะผู้ใช้ต้องจำทำนองเดิม · ต่างกันแค่ `hash` + `phraseKey` ⇒ เป็นไฟล์ละภาษาบนเครื่อง เพราะประโยคกระซิบต่อท้ายคนละภาษา · ที่นี่เก็บแค่ **ข้อความ** (`ANCHOR_PHRASE_TH/EN`, `anchorPhraseFor`, `anchorPhraseKey`) — TTS จริงเป็นงานเซิร์ฟเวอร์ (L1.5 `POST /ai/tts` แคชต่อ ประโยค·เสียง·ภาษา)

### `renderSignaturePcm`
additive synthesis ล้วน ไม่มี `AudioContext` (รันใน vitest บน VPS ได้ = พิสูจน์ได้ว่าเหมือนกันทั้งสองฝั่ง) · โน้ตซ้อนกันผ่าน release ให้ประโยคหายใจได้ · เฟดขอบ 10 ms **ก่อน** แล้วค่อย normalize พีคเป็น 0.7 ⇒ ตัวอย่างแรก/สุดท้าย = 0 เป๊ะ และพีค = 0.7 เป๊ะ (เหลือ headroom ให้ player คูณระดับเสียงคืนนั้นทับ) · sampleRate ฉีดได้ (ทดสอบ 22.05 kHz แล้วยาว/ขอบถูกต้อง)

### ตัวเลขที่วัดได้ (20,000 seed)
- **hash ไม่ซ้ำ 20,000/20,000**
- ทำนองไม่ซ้ำ **3,707 แบบ** ⇒ ข้อควรรู้: *ทำนอง*ไม่ใช่ของเฉพาะตัว — คนละคนอาจได้โน้ตชุดเดียวกัน แต่ลายน้ำเต็ม (ทำนอง × เอนเวโลป × เนื้อเสียง) ไม่ซ้ำ ถ้าวันหนึ่งต้องการให้ *ทำนอง* ไม่ซ้ำด้วยต้องขยายเป็น 5 โน้ต หรือเพิ่มสเกลอีกชุด (ยกเป็นหนี้ข้อ D1)
- ก้าวโน้ตสูงสุด 7 เซมิโทน · โน้ตสุดท้าย = โน้ตแรก 0 ครั้ง · midi 55–84 · ยาว 1200–1800 ms ทั้งหมด
- 40 เรนเดอร์: พีค 0.7000 ทุกไฟล์ · DC offset ≤ 0.00002 · ไม่มี NaN

`ANCHOR_VOLUME_MIN/MAX = 0.08/0.35` ฮาร์ดโค้ดซ้ำกับ `VOLUME_MIN/MAX` ใน `types.ts` โดยเจตนา (§0.5 S6 เพดานต้องอยู่ในเครื่องยนต์ ไม่ใช่แค่ UI) · `clampAnchorVolume(NaN) = 0.08` (ค่าเสียก็ต้องเบา ไม่ใช่ดัง)

## 2. `memorization.ts` — ทดสอบจำเสียง หน้าละข้าง

สถานะ: `IDLE → PLAYING → ASKING → PASSED`
- `start()` → สุ่ม `rounds` 2–5 + `gapsMs` (rounds−1 ตัว · 1000–3000 ms) + `pan` (L = −1 · R = +1 ได้จาก `side` เท่านั้น ไม่มีทางตั้งจาก setting — ถ้าสองหน้าเล่นช่องเดียวกันได้ การทดสอบก็ไม่พิสูจน์อะไร) → `PLAYING`
- `ask()` = แอปบอกว่าเล่นจบแล้ว → `ASKING` (เครื่องยนต์ยอมรับคำตอบตั้งแต่ `PLAYING` ด้วย: คนที่นับเสร็จก่อนไม่ผิด)
- `answer(n)` — `n` ต้องเป็นจำนวนเต็ม 1–5 ไม่งั้น **โยน error** (ชิปบนจอมีแค่ 1–5 ค่าอื่นคือบั๊กฝั่งเรียก ไม่ใช่ input ผู้ใช้) · `attempts` +1 ทุกครั้งที่ตอบ (ถูกหรือผิด)
  - ถูก → `PASSED` · `result()` = `EarTest {side, rounds, answer, attempts, volume}`
  - ผิด → **สุ่มรอบใหม่ + ช่วงใหม่** แล้วกลับ `PLAYING` (เล่นข้างนั้นซ้ำ)
- `result()` ก่อน `PASSED` โยน error (ห้ามบันทึกแถวที่ยังไม่ผ่าน)
- `volume` เข้ามาแล้วผ่าน `clampAnchorVolume` ทันที ⇒ ค่าที่บันทึกลง `EarTest` คือค่าที่เล่นจริง ไม่ใช่ค่าที่ขอมา

**ทำไมต้องสุ่มใหม่ตอนตอบผิด**: จำนวนรอบคงที่ = เดาได้ ⇒ ผู้ใช้ผ่านหน้าโดยไม่ได้ยินอะไรเลย · แต่ถ้าสุ่มใหม่แบบ "ห้ามซ้ำเดิมเด็ดขาด" การแจกแจงจะเบ้และเดาได้อีกแบบ ⇒ ใช้ "สุ่มแล้วถ้าซ้ำ สุ่มซ้ำอีกครั้งเดียว" · วัดจริง 100,000 ครั้ง: ซ้ำเดิม **6.43%** (ข้อสอบ M6 ยอมได้ถึง 60%) และการแจกแจงยังเท่ากัน: 2 = 24.9% · 3 = 25.0% · 4 = 25.2% · 5 = 24.8% (M2 ต้อง > 15% ทุกค่า)

หมายเหตุสเปก: APP-RUN §2 ใบ L1.6 เขียน "ต้องถูก 2 รอบติด" แต่ DESIGN §3.2 (มติ 24 ก.ย. รอบ 13) เขียน "ตอบถูก 1 ครั้ง = ข้างนั้นผ่าน" · ข้อสอบ M4 บังคับ `attempts: 1` ⇒ ทำตาม DESIGN + ข้อสอบ (ถูก 1 ครั้งผ่าน) และบันทึกความขัดกันไว้ที่นี่

## 4. `cueGate.ts` — ด่านเสียงชั้น engine

ฟังก์ชันบริสุทธิ์ 1 ครั้ง 1 คำตัดสิน 1 รหัสเหตุผล · ไม่มีนาฬิกาของตัวเอง (`nowT`/`guardUntilT` เป็นวินาทีบนนาฬิกาของผู้เรียก) · ทั้งตัวควบคุมเสียง (L2.6) และ player (L1.7) เรียกตัวนี้ = สองชั้นที่พูด "ไม่" ได้ และไม่มีที่ไหนเดาว่า "ได้"

ลำดับตรวจ (ตัวแรกที่ตกคือเหตุผลที่รายงานตอนเช้า):

| # | รหัส | ตกเมื่อ |
|---|---|---|
| 1 | `STATE` | `state !== 'REM_LIKELY'` (รวม `CUE`/`COOLDOWN` — ถ้าผ่านจะกระซิบซ้อนกัน) |
| 2 | `CONTROL` | `mode === 'CONTROL'` — คืนควบคุม: ตัดสินเหมือนเดิมทุกขั้น บันทึก `played: false` แต่ไม่เล่น (DESIGN §5.1 นี่คือสิ่งที่ทำให้ตอบได้ว่ากระซิบได้ผลจริงไหม) |
| 3 | `GUARD` | `nowT < guardUntilT` (3 ชม.แรก หรือ guard สั้น 20 นาทีหลังตื่นซ้ำ) |
| 4 | `MOTION` | `motionRecentSec < 120` — ขยับเมื่อกี้ = กำลังจะตื่น กระซิบตอนนี้คือปลุก |
| 5 | `HR_SPIKE` | `hrSpike` |
| 6 | `MAX_NIGHT` | `cuesThisNight ≥ 8` |
| 7 | `MAX_REM` | `cuesThisRem ≥ 3` |
| 8 | `SPACING` | `sinceLastCueSec < 300` |

ค่าคงที่ `CUE_MOTION_QUIET_SEC=120` · `CUE_SPACING_SEC=300` · `MAX_CUES_PER_NIGHT=8` · `MAX_CUES_PER_REM=3` ย้ายไปอยู่ `types.ts` ข้าง ๆ `VOLUME_MIN/MAX` แล้วให้ทั้ง `cueGate` และ `DEFAULT_NIGHT_PARAMS` อ่านตัวเดียวกัน (`cueSpacingMin = CUE_SPACING_SEC/60`) — ถ้าด่านเข้มกว่าพารามิเตอร์ (หรือกลับกัน) จะไม่มีใครเห็นจนไปนับจำนวนกระซิบในรายงาน · วางที่ `types.ts` เพราะถ้าวางใน `cueGate.ts` จะเกิด import วน (cueGate ต้องใช้ `NightState` จาก types) · `cueGate.ts` re-export ให้ครบเพื่อคนที่ import ไฟล์ตรง

ค่าที่อ่านไม่ได้ = ไม่ปลอดภัย: `NaN` motion → ถือว่าเพิ่งขยับ · `NaN` ตัวนับ → ถือว่าเต็มเพดาน · นาฬิกาเสีย → ถือว่า guard ยังไม่หมด · แต่ `Infinity` ผ่านได้ (เช่น `sinceLastCueSec = Infinity` = ยังไม่เคยกระซิบ)

เพิ่ม `NightState` (11 สถานะ) + `NIGHT_STATES` ใน `types.ts` ตาม DESIGN §5.1 — ก่อนหน้านี้ยังไม่มี union นี้ในเครื่องยนต์
